# Self-diagnosis endpoint, AI capability center, custom capabilities, task cost/breadcrumb, and runtime task submission

Five features delivered in one branch: a Feishu chain diagnosis HTTP endpoint with M5 test isolation in CI, a category-based AI capability view, CRUD for third-party AI capabilities with disk persistence and health probes, task cost attribution plus workflow breadcrumb in the detail page, and a runtime-console task submission form as a Feishu fallback. The implementation follows existing patterns (route handler delegation, `html` tagged templates, disk-persisted JSON stores, module-policy line budgets) and stays within the handler ceiling by compressing route calls into single-line blocks.

Watch for: SSRF via custom AI health checks (confirmed), crash on `/api/tasks/submit/options` when `modelPolicy` is undefined (confirmed), agent health probe always passes an empty manifest array rendering it inert (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The custom AI capability store accepts any valid URL at registration time and later issues outbound HTTP requests to that URL during health checks. Since the endpoint is local-only, the blast radius is limited to the machine owner — but the server can still be used to probe internal services or cloud metadata endpoints from localhost.

The task submission form's options endpoint calls `registry.list()` without a null guard. The handler passes `modelPolicy?.registry`, so when `modelPolicy` is not configured the server will throw an unhandled TypeError on `undefined.list()`.

The agent manifest health probe is wired into the handler with a hardcoded empty array (`manifests: []`), so the endpoint always returns an empty result. This appears to be placeholder wiring that hasn't been connected to the actual agent registry.

CI now runs `test:core` (ajun-runtime only); the M5 suites must be triggered manually via `npm run test:m5`. The handler file is at the line-limit boundary, with two route calls compressed onto a single line to stay within budget.

## SSRF surface in custom capability health checks

`CustomAiCapabilityStore.register()` validates that `endpointUrl` is parseable by `new URL(endpointUrl)` but does not restrict the protocol or target host. A local owner can register `http://169.254.169.254/latest/meta-data/` or `http://127.0.0.1:18082/v1/control` as an AI capability and then hit `POST /api/custom-ai/capabilities/:id/health-check`, which triggers a server-side fetch with a 3-second timeout and reports whether the response was `ok`. The response body is not returned, limiting data exfiltration to a binary healthy/unhealthy signal — but the request itself is made from the server process.

```typescript
// custom-ai-capability-store.ts, line 59
const url: any = entry.endpointUrl.replace(/\/+$/, '') + entry.healthCheckPath;
// ... fetch(url, { method: entry.healthCheckMethod, signal: AbortSignal.timeout(3000) });
```

In a deployment where the runtime runs in a container or cloud VM, localhost access may carry different trust assumptions. At minimum, restrict `endpointUrl` to `http:` and `https:` protocols and consider a denylist for RFC-1918, link-local, and metadata IP ranges.

## Task submit options crash path

```typescript
// runtime-http-task-submit.ts, line 6
const agents: any = await registry.list();
```

The handler passes `registry: modelPolicy?.registry`. When `modelPolicy` is `undefined` (some deployment modes, or test fixtures that don't include it), `registry` will be `undefined` and `.list()` throws a TypeError. This propagates as a 500 to the client. Fix:

```typescript
if (!registry) return { status: 200, payload: { agents: [] } };
```

## Inert agent health probe wiring

```typescript
// runtime-http-handler.ts, line 178
{ const r: any = await routeAgentHealthProbeApi({
    request,
    local: isLocalAddress(request.socket.remoteAddress),
    manifests: []  // always empty
}); if (r) return sendJson(response, r.status, r.payload); }
```

`probeAgentManifestHealth` filters manifests for `interaction.runtime === 'hermes-profile'` — with an empty input it short-circuits to `[]`. The endpoint exists, responds with `200 { results: [] }`, but does no actual probing. If the intent is to ship this as a placeholder for future wiring, it works; if it's meant to be functional in this PR, it needs the real manifest source (e.g., `modelPolicy.registry.list()`).

## Custom AI form HTML construction

`renderCustomCapabilities` in `app-access-views.ts` builds the registration form using `raw(...)`:

```typescript
form.innerHTML = raw(`<label>能力类型<input name="capabilityType" ...></label>...`).value;
```

The content is entirely static (no user-controlled interpolation), so this isn't an XSS vector in its current form. However, the project convention is to use the `html` tagged template for all DOM construction, with `raw()` reserved for pre-sanitized fragments. A future maintainer adding a dynamic default value inside this string would bypass escaping.

## Handler line-limit pressure

The handler file is at 750 split-lines (limit bumped to 755). The single-line compressed route blocks (`{ const r = ...; if (r) return ...; }`) and the two-routes-on-one-line pattern for custom AI + agent health probe are symptoms of the limit forcing code into less readable forms. The compressed style makes scanning the route order harder than the multi-line blocks above it in the same file.

## Test coverage gaps

Not tested: custom AI health check actually reaching an endpoint (would require mocking `fetch` at the store level), behavior when `registry` is undefined in task-submit, the frontend form submission flow, and the frontend diagnosis rendering (chain-diagnosis section in `app.ts`).
