# Engineering hardening and UI infrastructure across monorepo (v2)

All six issues from v1 have been addressed. The `html` tagged template migration is now complete: `task-record-detail-view.ts` and `boom-monitor-console.ts` use `html` tags throughout their rendering functions, `app-access-views.ts` correctly wraps pre-built HTML fragments in `raw()` with `escapeHtml()` applied inside those fragments for dynamic values, and the refresh scheduler cancels the pending timer at the start of `scheduleNext()`. The CI workflow now runs frontend build drift checks against all three apps.

Watch for: the escaping strategy in `app-access-views.ts` relies on a two-layer pattern (manual `escapeHtml()` inside plain backtick fragment builders, then `raw()` when interpolated into outer `html` templates) that is fragile for future maintainers (possible). The `renderBilling` function in `app.ts` still uses direct `innerHTML` assignment without the `html` tag in its provider-reconciliation branch (confirmed, low severity — values come from numeric coercion only).

**Verdict**: APPROVED

## High-level view

The `task-record-detail-view.ts` XSS regression is resolved — `renderAttentionDetail`, `renderAcceptanceDetail`, and `renderDiagnosisOutcome` now use `html` tagged templates with `raw()` reserved for sub-fragments built by the `html` tag. The boom-monitor `renderWorks` is fully migrated. The `app-access-views.ts` double-escaping problem is resolved by applying `escapeHtml()` inside the plain-backtick fragment builders and wrapping those fragments with `raw()` at interpolation.

The timer chain accumulation is fixed: `scheduleNext()` calls `cancel(timer)` before setting a new timeout. CI drift checks now cover all three apps.

## Fragment-builder escaping pattern

The fix for v1 issues 3–4 introduced a two-layer convention: build HTML with plain backticks and explicit `escapeHtml()` on every dynamic value, then mark the result as trusted with `raw()` when interpolated. If a contributor adds a new data attribute or text interpolation inside one of these fragment builders without `escapeHtml()`, the outer `raw()` will pass it through unescaped. The `html` tag could be used for these fragments too — `raw(html`<button ...>${action}</button>`)` would provide auto-escaping inside and trusted-markup outside in a single expression. Worth a comment or lint rule to flag plain-backtick templates assigned to variables that later get `raw()`-wrapped.

## `renderBilling` innerHTML pattern

In `app.ts`, the billing attribution HTML is assigned via:

```typescript
billingAttribution.innerHTML = providerReconciliation.status === 'gap'
    ? `<div><strong>发现 ${formatNumber(...)} 次账外调用</strong>...</div>...`
    : ...
```

The interpolated values pass through `Number()` then `toLocaleString('zh-CN')`, producing only digits, commas, and locale-specific separators. No user-controlled string reaches this path without numeric coercion. Migrating to the `html` tag would make this consistent with the rest of the file but doesn't fix an exploitable issue.

## Token distribution and CI coverage

The `distribute:tokens` script runs as the first step of `npm run check`, so by the time CI reaches the drift check step, all three `public/tokens.css` files are already freshly copied. A developer who edits `apps/ajun-runtime/public/tokens.css` instead of the canonical source gets no CI signal — the edit is silently overwritten. A dedicated "tokens drift" step (comparing `git diff --exit-code **/tokens.css` before `distribute:tokens` runs) would surface this, though the self-healing behavior may be intentional.
