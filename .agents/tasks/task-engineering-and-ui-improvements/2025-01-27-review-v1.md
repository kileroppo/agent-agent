# Engineering hardening and UI infrastructure across monorepo

This change adds CI automation (GitHub Actions, any-density gate), introduces a shared design-token package (`packages/ui-tokens`) distributed to all three apps, implements dark mode via `prefers-color-scheme`, creates an auto-escaping `html` tagged template literal to replace manual `escapeHtml()` calls, consolidates responsive breakpoints in ajun-runtime, and adds exponential backoff with an offline indicator to the refresh scheduler. The approach is additive — no existing CSS selectors or property values change, and the token layer sits above each app's existing variables via aliases.

Watch for: the `html` template migration left **multiple code paths using plain backtick templates with no escaping at all** (confirmed) — `renderAttentionDetail`, `renderAcceptanceDetail`, `renderDiagnosisOutcome`, boom-monitor `renderWorks`, and several sub-builders in `app-access-views.ts` (`modes`, `actions`, `connectionControls`, `modelAction`, `managementActions`) that produce HTML fragments interpolated into `html`-tagged outer templates without `raw()`. Both patterns are XSS regressions against the base branch which had explicit `escapeHtml()` on those values.

**Verdict**: NEEDS_CHANGES

## High-level view

The `html` tagged template is well-designed — symbol-guarded `raw()` marker, auto-escaping of everything else — but its integration was incomplete. Functions that still use plain backticks had their `escapeHtml()` calls stripped on the assumption the `html` tag would protect them, but those functions never switched to the `html` tag. Separately, functions that do use `html` interpolate pre-built HTML fragments (`modes`, `actions`, `connectionControls`, etc.) without `raw()`, which will double-escape their markup and break the UI.

The shared token pipeline (`distribute:tokens` → copy to `public/`) is wired into the root `check` script early enough that downstream tsc and build steps see the file. The alias layer means existing per-app variables keep working. CI drift-check only covers ajun-runtime's JS output, not the other two apps' token copies.

The exponential backoff in `refresh-scheduler` switches from `setInterval` to a `setTimeout` chain, capping at 60 s, with `onDegraded`/`onRecovered` callbacks surfacing connection state to the UI. However, the `visibilitychange` listener can trigger `refreshNow()` while a scheduled timeout is still pending, spawning parallel timer chains that accumulate over tab-focus cycles.

The any-density gate counts once per line regardless of multiple occurrences on the same line — a known blind spot documented by its test suite.

## Incomplete `html` tag migration leaves unescaped innerHTML paths

Three helper functions in `task-record-detail-view.ts` — `renderAttentionDetail`, `renderAcceptanceDetail`, and `renderDiagnosisOutcome` — still use plain backtick templates for their return value, but the PR removed every `escapeHtml()` call from their interpolations. On the base branch (24bfadc), each of these functions passed all API-sourced values through `escapeHtml()`:

```js
// Base branch (secure):
return `...
    <h3>${escapeHtml(attention.headline)}</h3>
    <p>${escapeHtml(attention.cause)}</p>
...`;
```

```js
// This PR (unescaped):
return `...
    <h3>${attention.headline}</h3>
    <p>${attention.cause}</p>
...`;
```

These values come from the runtime API (`/api/task-records/...`) and include user-provided task descriptions, error messages, and URLs. `renderDiagnosisOutcome` additionally interpolates `paperclipIssue.detailUrl` into an `href` attribute without sanitization, which could allow `javascript:` scheme injection.

The same regression appears in `boom-monitor-console.ts` `renderWorks()`, where `workTitle` (derived from `work.title`) is interpolated into element content and `aria-label` attributes without escaping.

## Pre-built HTML fragments missing `raw()` in `html`-tagged templates

Several functions in `app-access-views.ts` build HTML fragment strings using plain backticks (e.g., the `modes` variable containing `<select>` markup, `actions` containing `<button>` elements), then interpolate them into an outer `html`-tagged template. Because the `html` tag escapes all non-`raw()` values, the resulting innerHTML will contain literal `&lt;select&gt;` text instead of functional form controls.

Affected instances in `app-access-views.ts`:

- `aiServiceCard`: `${modes}` and `${actions}` at line 102
- `renderEmployeeConnections`: `${modelAction}` at line 201 and `${connectionControls}` at line 205
- `campaignCard`: `${actions}` at line 160
- `accountConnectionCard`: `${managementActions}` inside a ternary at line 314, `${primaryAction}` just above

Each needs `raw()` wrapping. The fragments themselves also need internal escaping of their dynamic values (which they currently lack since the `escapeHtml` calls were removed from them too).

## Exponential backoff timer lifecycle

The scheduler's `refreshNow()` ends with `scheduleNext()` in the `finally` block, setting a new timeout. But `refreshNow()` is also triggered by the `visibilitychange` listener. If the page becomes visible while a scheduled timeout is pending, `refreshNow()` fires, and its `finally` block calls `scheduleNext()` — creating a second concurrent timer chain without cancelling the first:

```
timer = schedule(() => refreshNow(), computeDelay());  // pending
// ... visibilitychange fires ...
refreshNow() → finally → scheduleNext() // new timer, old still ticking
```

The `running` guard prevents overlapping refresh calls, but doesn't prevent overlapping timers. Over time, after several tab-focus/blur cycles, multiple timer chains accumulate. Fix: cancel the existing timer at the start of `scheduleNext()`.

## Dark mode token layering

The `ajun-runtime/styles.css` dark-mode block defines its own literal hex values for `--canvas`, `--ink`, `--mint`, etc. rather than referencing the token layer via `var()`. A palette change requires updating both `packages/ui-tokens/tokens.css` and the app-specific dark block independently, with no automated check that they stay in sync. The tokens file sets `--color-canvas: #121a16` in dark mode and the alias `--canvas: var(--color-canvas)` — but then `styles.css` overrides `--canvas: #121a16` directly, making the token indirection moot for this app in dark mode.
