# 新建一个 Agent 员工：可复制模板

> 用法：先复制本文件，改名为 `agents/<员工编号>/岗位卡.md`。
> 先把第一部分到第五部分填清楚，再创建 Hermes Profile 和飞书 Bot。
> 没有完成真实样板任务前，员工必须保持“草案”，不能接正式工作。

## 0. 一句话说清这名员工

- **给用户看的名字：** 例如：小D·视频整理助手
- **内部编号：** 例如：`video-transcriber`
- **它替负责人稳定完成什么重复工作：**
- **第一件最小工作：** 例如：把一条公开短音频转成 `转录结果.md`

## 2. 最小样板任务

这一步只验证员工能真正干第一件事。不要加复杂审批、多人协作或一堆工具。

```text
负责人给什么：

员工应该先回复的计划：

负责人怎样确认开始：

员工实际要做的 3–5 步：

最后必须留下的文件或文档：

怎样检查结果是真的：
```

### 最小样板通过标准

- [ ] 员工先说清自己的计划
- [ ] 未经确认不开始处理
- [ ] 真实产物已经生成
- [ ] 产物能打开、内容不是空的
- [ ] 做不成时说出真实原因，没有假装完成

## 3. 工作步骤

把整个工作拆成 5–12 步。每一步都要能看出“做到了没有”。

```text

→
→
→
→
交付结果
```

## 4. 员工的大脑

这部分写进它独立 Hermes Profile。只写它怎么判断和做事，不要把密钥、账号、Cookie 写进去。

```text
你是谁：

你的职责：

收到任务后先做什么判断：

什么时候必须追问：

什么时候必须拒绝：

做完后怎样自检：

没有通过自检时绝不能说什么：
```

### 创建时交给 Codex 的话

```text
帮我创建一个 Hermes Agent。

名字：<给用户看的名字>
内部编号：<内部编号>

先只做接线样板：创建独立 Profile、独立飞书 Bot、独立工作目录和模型配置。
默认保持 draft，工具白名单为空，不承接正式业务任务。

完成私聊真实收发测试；如果这个岗位需要团队协作，再完成群内 @ 收发测试。
不要复制其他员工的账号、密钥、Cookie、会话或用户信息。
完成后只报告：Profile、飞书入口、私聊/群聊测试、以及尚未具备的业务能力。
```

## 8. 上线决定

只有下列问题全部回答“是”，才能从 `draft` 变成“可以接工作”：

- [ ] 用户在飞书能找到它并正常私聊
- [ ] 它只做自己岗位内的事
- [ ] 它能完成最小样板，交出真实结果
- [ ] 它失败时不会编造完成
- [ ] 它交付的文档或文件能打开
- [ ] 风险操作不会绕过负责人确认

如果其中任何一项没有通过，保持 `draft`，把卡点写进验收账本；不要为了显示“军团有人”把它提前上线。
