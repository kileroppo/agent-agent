# Agent 搭建与上线流程

| 字段 | 内容 |
| --- | --- |
| 状态 | v1 实现基线，小D Manifest 已校验，待 Hermes/飞书实机验证 |
| 版本 | v1.0 |
| 最后更新 | 2026-07-18 |
| 适用范围 | Agent军团内所有业务 Agent |

## 1. 结论

每个 Agent 不是复制一段 Prompt 就算完成，而是由六部分共同组成：

1. **岗位定义**：做什么、不做什么、接什么任务；
2. **运行身份**：独立 Hermes Profile、模型、记忆和会话；
3. **能力边界**：Skill 与工具白名单、数据范围；
4. **业务执行器**：位于 `apps/` 的确定性流程和产物生成；
5. **治理规则**：审批、预算、质量门禁、失败处理；
6. **入口与交付**：飞书消息、卡片、文档和附件。

仓库中的版本化配置是真正的“岗位说明书”；Hermes 和飞书是运行投影，不能只在平台后台手工配置而不留版本记录。

### A君也不例外

A君不是普通员工，不能被派给某一件业务工作；但它同样必须有岗位定义、独立大脑、允许调用的能力、不能做的事、样板工作和验收记录。区别只有一条：A君负责安排已上岗员工，不代替他们假装完成专业工作。

## 2. 标准目录

一个 Agent 激活后至少应有：

```text
agents/<agent-id>/
├── manifest.json          岗位、任务、权限、审批和质量规则
├── prompts/
│   ├── system.md          稳定角色与行为边界
│   └── task-guides/       按任务类型拆分的工作说明
├── evals/                 典型、边界和失败样例
└── README.md              面向维护者的使用与下线说明

apps/<agent-app>/          可独立运行和验收的业务执行器
```

不是每个 Agent 都必须拥有独立应用。只调用标准工具且没有专属业务状态机的轻量岗位，可以只声明 Manifest 和 Prompt；需要长任务、领域算法、产物或 checkpoint 的岗位必须有 `apps/` 执行器。

## 3. AgentManifest 最小设定

字段语义以[核心契约](../docs/contracts/core-contracts.md)为准。实际文件至少需要表达以下内容：

```json
{
  "schemaVersion": "agent.army/v1",
  "agentId": "xiaod",
  "name": "小D",
  "department": "内容组",
  "role": "音视频素材转录与整理专员",
  "responsibilities": [],
  "nonResponsibilities": [],
  "acceptedTaskTypes": [],
  "toolAllowlist": [],
  "dataScopes": [],
  "approvalPolicies": [],
  "qualityGates": [],
  "budgetPolicy": {},
  "promptRef": "agents/xiaod/prompts/system.md",
  "runtimeProfileRef": "integrations/hermes/profiles/xiaod.profile.json",
  "appRef": "apps/xiaod-media-transcriber",
  "owner": "pending",
  "status": "draft"
}
```

这里的空数组表示“尚未完成设定”，不是默认放行。工具和数据权限遵循默认拒绝。

## 4. 从需求到上线的生产线

### 阶段 A：岗位设计

- 用一句话写清岗位结果，而不是写人格故事；
- 列出 3–7 项职责和明确的非职责；
- 将输入归并成有限的 `taskType`；
- 定义每类任务的可验收产物；
- 指定业务负责人和下线条件。

**门禁：** 无法明确输入、输出和完成标准时，不进入搭建。

### 阶段 B：权限与风险

- 只开放完成任务必需的工具；
- 明确可读取、写入和外发的数据范围；
- 把公开发布、外部发送、敏感读取、扩权和高成本动作列为审批项；
- 设置单任务预算、重试上限和超限处理。

**门禁：** 权限不能靠 Prompt 自觉约束，必须能由运行层或适配层阻断。

### 阶段 C：运行装配

- 创建独立 Hermes Profile；
- 绑定版本化 Prompt、Skill 和工具白名单；
- 绑定模型与降级模型，但不在 Manifest 中保存密钥；
- 如有领域流程，绑定 `appRef`；
- 设置任务调度、heartbeat、超时和失败重试。

**门禁：** Profile 配置必须能从仓库基线重复生成，禁止只存在于某台机器的手工配置。

### 阶段 D：飞书接入

- 将用户或群聊路由到稳定的 `agentId`；
- 将自然语言请求解析为受支持的 `taskType`；
- 缺少必要输入时进入 `needs_input`，不猜测执行；
- 只展示少量用户阶段，技术细节进入任务详情；
- 交付前验证飞书文档、附件和接收人权限。

**门禁：** 重复事件不能重复创建任务或产物。

### 阶段 E：测试与试运行

- Manifest schema 校验；
- Prompt/工具越权测试；
- 典型、边界、失败、重试和重复事件测试；
- 真实飞书端到端任务；
- 产物质量和权限验证；
- 小流量影子运行或人工复核。

**门禁：** 测试通过前状态只能是 `draft`，不能对组织公开承接任务。

### 阶段 F：激活与迭代

- 将状态改为 `active` 并记录版本；
- 监控成功率、人工返工率、成本和越权拒绝；
- 修改职责、工具、审批或完成标准时走版本评审；
- 暂停用 `paused`，永久停用用 `retired`，保留历史任务和产物引用。

## 5. 灵活与规则的边界

### 必须固定

- Agent ID、任务 ID、状态和契约版本；
- 工具白名单、数据范围和审批阻断；
- 产物完成定义、幂等、审计和秘密管理；
- 终态与失败记录不能由模型随意改写。

### 允许灵活

- 模型如何拆解普通步骤；
- 在白名单内选择哪种工具及调用顺序；
- 表达风格和中间推理策略；
- 低风险失败时，在预算与重试上限内选择恢复方式。

原则是：**结果与边界用规则控制，边界内的工作方法允许 Agent 自主。**

## 6. 小D作为第一条样板线

M1 不只交付一个能在飞书里说话的小D，还要验证这条生产线：

1. 仓库中的小D Manifest 能生成或校验 Hermes Profile；
2. 飞书请求能稳定路由为标准任务；
3. 小D执行器能保存 checkpoint 并生成可验证产物；
4. 失败、重试、审批和交付均遵循统一契约；
5. 第二个 Agent 可以复制流程，但不复制小D业务代码。

在这五项通过前，“如何搭建每个 Agent”仍属于设计基线，不应声称已经工程验证。
