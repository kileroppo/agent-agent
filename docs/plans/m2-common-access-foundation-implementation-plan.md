## 1. 这份计划解决什么

先搭一套所有 Agent 共用的底座，再接具体网站验证。底座由三块组成：

1. **账号管家**：统一接收和管理网站登录连接；业务 Agent 永远拿不到 Cookie、密码或 token。
2. **内容获取中心**：业务 Agent 只说“读取这个链接的哪些内容”；中心决定使用哪个允许的工具和通道。
3. **Agent 运维官**：统一发现登录失效、适配器故障和重复失败，并只做安全的恢复动作。

YouTube 是第一个**通用通道**验证平台，不是底座的产品边界，也不是底座编码的起点。2026-07-27，小红书已作为首个明确授权的固定平台完成 MediaCrawlerPro 深度读取、撤销和重新授权恢复验收；其他平台仍须逐项验收。

## 1.1 当前实施证据（2026-07-20）

| 阶段 | 当前事实 | 已有证据 | 未证明部分 |
| --- | --- | --- | --- |
| P0 | 小D保持本地文件/公开 URL 兼容；新增通用访问模块与独立测试入口 | `integrations/access/` 测试、`apps/xiaod-media-transcriber` 回归测试 | 真实发布形态、统一启动器 |
| P1 | 已实现浏览器会话**引用**和 CookieBridge 账号标识连接、最小权限检查、查看与撤销；不保存或返回原始凭据 | `ConnectionStore`、`ConnectionBroker`、本地 API 验证 | 官方浏览器伴侣、OAuth、系统密钥链的真实凭据存储 |
| P2 | 已实现适配器注册、深度优先/通用兜底路由、统一内容包和安全失败；CookieBridge → MediaCrawlerPro 仅在 loopback 内部临时传递登录态 | `ContentAcquisitionCenter` 契约测试；小红书真实读取、撤销、获取前拒绝、重新授权和恢复任务 | 其他登录型平台的实际结果 |
| P3 | 已实现脱敏健康事件、通道切换和撤销事件记录 | `OperationsEventStore`、本地 API 验证 | 自动组件重启、连续失败聚合的真实运行策略 |
| P4 | 小D URL 路径已改由内容中心调用；内置 `yt-dlp` 通用适配器可按获准浏览器会话选择器执行 | 小D回归、适配器测试、隔离本地服务检查 | 真实 YouTube 登录态、受限视频读取和失效恢复 |

当前浏览器会话连接只保存 `browser-session` 类型的不可回显引用；实际读取时由受控 `yt-dlp --cookies-from-browser <browser>` 在本机内部使用浏览器会话。它不传递或记录 Cookie，但仍需要用户本人确认该浏览器与 YouTube 账号可被用于只读验证。它是 M2 的首轮受控桥接，不等同于最终的官方浏览器伴侣或 OAuth 产品形态。

## 2. 实施顺序

```text
P0 明确运行时边界与测试底座
  → P1 账号管家
  → P2 内容获取中心
  → P3 运维官
  → P4 接入 YouTube 通用读取适配器与小D
  → P5 用真实 YouTube 视频验收
  → P6 接入并验证一个 MediaCrawlerPro 深度平台
```

P0–P3 是通用底座；P4–P6 是用平台证明底座。未完成 P0–P3，不开始要求用户登录或测试真实 YouTube 账号。

## 3. 分阶段计划

### P0：运行时边界与测试底座

**做什么**

- 盘点现有 `apps/xiaod-media-transcriber`、Hermes、飞书适配和本地媒体路径，明确哪些保持 M1 原样；
- 建立受控配置、脱敏日志、组件健康检查和本地测试启动方式；
- 为连接、内容请求、内容包和运维事件建立契约测试夹具，只使用虚构数据；
- 确认代码落点：平台接入放 `integrations/`，运行与恢复工具放 `ops/`；只有出现第二个真实消费者后才抽取 `packages/`。

**完成标准**

- M1 本地文件和公开来源路径不被改坏；
- 测试和日志中不存在真实凭据、授权链接或私密内容；
- 组件健康不再被误当作“外部内容已读取成功”。

### P1：账号管家

**做什么**

- 实现连接记录：平台、账户别名、允许 Agent、允许读取动作、数据范围、有效期、状态和安全凭据引用；
- 实现连接状态：未连接、可用、即将过期、已过期、已撤销、不可用；
- 实现 `ConnectionBroker`：每次读取前检查“哪个 Agent、用哪个连接、做什么只读动作、是否仍有效”；
- 接入本机受控密钥存储的抽象层；业务任务、飞书、Prompt、日志和文档只保存连接引用与脱敏状态；
- 预留受控浏览器/OAuth/本机导入三类登录输入接口，但此阶段不把任一工具的原始输出暴露为公共 API。

**完成标准**

- 允许、越权、缺连接、过期、撤销均有可测试的明确结果；
- 业务 Agent 只能拿到“本次读取获准/拒绝”的结果，不能拿到原始登录信息；
- 用户后续看到的补充动作是“重新授权”，不是“把 Cookie 发给我”。

### P2：内容获取中心

**做什么**

- 实现统一入口：`fetch(source, requestedCapabilities, connectionId?)`；
- 实现平台注册表：识别 URL、登记可提供的能力、登录要求、健康状态和通道级别；
- 实现统一 `ContentPackage` 与安全失败结果；
- 固定路由规则：固定支持平台的深度适配器优先；不可用或不支持时，按能力范围调用通用适配器；
- 让上层 Agent 只能请求 `basic_content`、`images`、`media`、`subtitles`、`comments` 等能力，不能指定 `yt-dlp`、MediaCrawlerPro 或浏览器工具。

**完成标准**

- 不同底层工具的结果都能交成同一种内容包；
- 通用通道只如实说明本次已提供的能力，不能被标成“假失败”；
- 用户明确要求而所有允许通道都做不到的能力，才返回“该能力当前不可用”。

### P3：Agent 运维官

**做什么**

- 将连接过期、适配器不可用、通道切换和连续失败统一转换成脱敏健康事件；
- 提供安全动作：通知、诊断、有限次数重试、重启 A君自管组件；
- 把需要用户完成的动作明确交回用户：重新登录、验证码、二次验证、付费权限或授权扩大；
- 为重复平台故障建立聚合规则，避免每个业务 Agent 各自报一遍错误。

**完成标准**

- 运维官可以说明“哪个连接或组件需要处理、下一步做什么”，但不能读凭据或内容；
- 连接健康、读取失败和业务任务失败保持三种不同事实；
- 所有恢复动作可追溯，且不会自动扩大权限。

### P4：接入 YouTube 通用读取适配器

**做什么**

- 将 YouTube 登记为第一个通用读取平台；
- 用受控适配器在内部复用 `yt-dlp` 的公开或已授权媒体/字幕获取能力；需要浏览器登录态时，只允许账号管家批准的执行器使用；
- 初始只支持读取：视频基本信息、描述、字幕；缺字幕时可在获准范围内交由媒体 Worker 获取音频后转录；
- 将统一内容包交给小D，保留其现有本地文件/公开视频路径作为独立兼容路径；
- 不做评论读取、发布、点赞、订阅、私信、账号设置或任意浏览器脚本能力。

**完成标准**

- 小D 不知道底层是否使用 `yt-dlp` 或受控浏览器；
- 需要登录但未授权时，任务稳定进入“需要重新授权/改用本地文件”，而非卡住或索要 Cookie；
- 该适配器可以被替换，不要求修改小D业务流程。

### P5：YouTube 真实闭环验收

**前提**

- A 君明确授权使用其拥有访问权的一个 YouTube 视频及只读范围；
- 用户本人在 A君受控入口完成登录；不在聊天、终端输出或文档中提供凭据。

**验收路径**

```text
用户提交 YouTube 链接
→ 内容中心识别 YouTube 与所需能力
→ 账号管家检查只读连接
→ YouTube 通用适配器获取内容包
→ 小D转录/整理并交付
→ 验证连接失效或撤销后给出重新授权提示
```

**验收结论边界**

- 通过后，可证明通用账号管家、通用内容获取和运维恢复在 YouTube 读取场景可用；
- 不可因此宣称 MediaCrawlerPro 深度通道、评论能力或所有平台均已验收。

### P6：深度通道验收

**做什么**

- 已实现 MediaCrawlerPro 固定平台（小红书、抖音、哔哩哔哩、快手）的受控适配器：账号管家仅登记 CookieBridge 账号标识；执行时由适配器从本机 CookieBridge 临时取值并立即转交本机 DownloadServer；
- 后续由 A 君指定一个可合法只读验证的平台和范围，对正文/媒体之外的已声明能力（例如评论）做单独验证；
- 验证深度通道不可用时，内容中心按能力规则切到通用通道并创建运维事件。

**完成标准**

- 深度优先、通用兜底的路由规则获得真实证据；
- 深度能力和通用能力的差异被如实标注；
- 至此才可宣称 M2 的双通道内容获取闭环完成。

## 4. 每阶段的测试门

| 阶段 | 自动化必须证明 | 运行时必须证明 | 不得冒充已经证明的事 |
| --- | --- | --- | --- |
| P0 | 契约夹具、脱敏、M1 回归 | 本地组件可启动与健康输出 | 外部平台可用 |
| P1 | 策略允许/拒绝、过期、撤销 | 安全引用可被受控使用 | 某个视频一定可读 |
| P2 | 平台识别、路由、内容包、能力缺失 | 适配器可被调用与返回安全结果 | 已登录或深度平台已验证 |
| P3 | 事件分类、重试上限、无扩权 | 诊断与恢复动作有记录 | 运维官能替用户登录 |
| P4 | YouTube 适配器与小D契约 | 本地受控调用不泄密 | 真实 YouTube 账号连接成功 |
| P5 | 回归测试 | 真实只读 YouTube 任务、失效/撤销恢复 | 深度通道或所有平台可用 |
| P6 | 深度/兜底路由和能力差异 | 一个固定平台深度读取与切换 | 所有固定平台均支持 |

## 5. 停止规则

- 遇到验证码、二次验证、付费墙、地区限制或平台拒绝：停止自动处理，提示用户本人处理或改用允许来源；
- 发现某底层工具需要输出原始 Cookie 才能工作：停止该接法，先修正账号管家边界；
- 深度适配器不能提供用户要求的能力：按能力表尝试允许的通用通道；无通道支持则如实结束；
- M1 回归失败：停止 M2 扩展，先恢复 M1；
- 未经明确授权：不连接真实账号、不抓取私密内容、不外发任何内容。

A君已提供白名单平台登录、刷新已登录账号、创建连接、续期、暂时禁用和撤销的正式本机入口；小红书已完成从零登录、真实读取、撤销恢复和同 ID 续期。来源链接敏感参数安全保存按所有者决定后续处理。
