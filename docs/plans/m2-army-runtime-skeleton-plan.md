# M2 Paperclip 军团总控接入计划

| 字段 | 内容 |
| --- | --- |
| 状态 | 实施中 |
| 日期 | 2026-07-20 |
| 目标 | 以 Paperclip 承担军团的组织、任务、heartbeat、预算、审批和审计总控；飞书承担日常派活与交付；A君作为可扩展本机能力底座、执行适配、授权、诊断和恢复页面。 |

## 已有基础

- A君已有岗位 Manifest 读取、过渡期本地任务视图、基础路由、高风险拦截、结果与故障恢复页面；
- 任务协调官、架构师、审核官、运维官和小D已有岗位定义；
- 当前本地任务存储和 Paperclip 任务投影只是过渡骨架，不能被当作军团控制面。
- 已在本机 Paperclip `2026.707.0` 注册 `A君本机健康官` HTTP Agent，并验证 `AGE-18`：Paperclip 自动 heartbeat 调用 A君本机接口，A君回报同一任务单并完成。重复 heartbeat 只产生一条 A君业务执行回报。

## 实施顺序

1. **Paperclip 能力验真**：已验证公司、Agent、任务、heartbeat、HTTP Adapter、审计和回报的真实 API/行为；本次版本为 `2026.707.0`。预算和审批单列为下一轮验证。
2. **组织与岗位接入**：已创建首个受限 `A君本机健康官`；后续映射其余岗位及权限、预算和汇报关系，仓库 Manifest 保留为岗位定义来源，避免双向手工维护。
3. **首个执行切片**：已实现 A君 本机 HTTP 适配器。它只接受 loopback Paperclip heartbeat，执行低风险健康检查，回报阶段与结果到同一 Paperclip 任务；同一任务的并发/已完成 heartbeat 不重复执行业务动作。
4. **控制台收口**：A君 只保留“连接授权、组件健康、恢复失败、查看脱敏诊断与业务产物”的本机入口；飞书承担日常交办、补充输入和交付，组织图、任务排程、Agent 生命周期、预算、审批和审计只在 Paperclip 管理，不在 A君重复实现。
5. **安全闭环**：先验证一个只读、明确授权的任务；再验证预算封顶、审批拒绝、暂停/恢复和失败回报。外发、发布、删除、付款、扩权仍不得自动执行。
6. **业务接入扩展**：小D 成为第一个真实业务执行 Agent；第二个真实消费者出现后，才把可复用适配协议抽到 `packages/`。

## 非目标

- 不自研与 Paperclip 重复的军团控制台、组织树、任务队列、定时调度、预算、审批或审计系统；
- 不把未验证的岗位标成真实可持续运行的 `active` 执行 Agent；
- 不迁移或删除小D既有任务和数据；
- 不接入 OAuth、浏览器会话、飞书写入或其他外部副作用，除非得到单独授权并完成对应验证。

## 验收

1. Paperclip 中能看到 Agent军团组织、首个执行 Agent、其预算和任务归属；
2. 创建一个低风险任务后，Paperclip heartbeat 能唤醒 A君 执行适配器，且同一任务不会被重复领取；
3. A君 回报的阶段、失败和可验证产物引用能显示在 Paperclip；部分成功不得标成完成；
4. 预算到线、审批拒绝、Agent 暂停和恢复均不会触发未经授权的外部动作；
5. A君 页面不再提供组织、排程、预算、审批或审计的重复管理入口，而是明确跳转/展示 Paperclip 总控入口；
6. 自动化测试、Paperclip API、A君本地 API 和真实浏览器路径均通过。
