# M2 第一批 Agent 创建与治理闭环实施计划

| 字段 | 内容 |
| --- | --- |
| 状态 | 实施中：草案、受限测试、军团总管、普通与组织级审批切片已完成本机验证；真实飞书验收待完成 |
| 关联 PRD | `tasks/prd-m2-first-batch-agent-governance.md` |
| 目标 | 验证一条“飞书军团总管 → 路由 → 审批（按需）→ 执行 → 飞书交付”的真实闭环；其中创建 Agent 走 Paperclip 审核、受限测试与上线 |

## 变更契约

- 用户结果：只用手机飞书即可下任务、查看状态、处理审批并收到结果；可在同一会话提出新岗位需求，并只在审核和验收通过后得到可调用 Agent；
- 不变量：飞书军团总管是唯一日常入口；小D直达闭环不被破坏；普通一次性审批不投影 Paperclip；Paperclip 只管组织级治理；A君只提供本机能力；未批准 Agent 不可运行生产任务；
- 证据：契约/单元测试、Paperclip API 记录、A君/Hermes 测试实例、真实飞书验收和产物验证分别记录；
- 外部边界：创建/发布飞书应用、修改权限、外发、账号登录、扩权和付费动作须重新取得所有者授权。

## 实施切片

1. **飞书军团总管与普通审批切片（优先）**
   - 建立单一 Hermes 飞书入口：私聊直达、群内仅响应 @ 提及；Mac 不在线时返回明确不可执行或已排队状态；
   - 将飞书文本交给协调官，至少稳定路由“小D素材处理”“运维健康检查”“创建 Agent”三类任务；总管仅派单，不作为业务执行器；
   - 建立 `ApprovalContract` 的 `local` 路径：飞书审批卡 → A君持久化审批 → 范围/有效期校验 → Hermes 继续或取消任务 → 原会话回报；
   - 实现飞书卡片按钮的幂等回调、重复点击、过期、拒绝和 Mac 离线补偿；不得从卡片提交或回显凭据。

2. **治理岗位正式化**
   - 为创建官、架构师、审核官、运维官、协调官补齐 SOP Prompt、输入输出 schema、工具白名单和评测；
   - 运维官新增修复能力前，先在 `LocalCapabilityProviderContract` 登记并限制为 A君自管组件。

3. **草案与组织级审核**
   - 实现 `AgentProposalContract` 存储、版本和状态机；
   - 飞书创建入口只生成草案；
   - Paperclip 适配：草案映射为招聘审核，技能仅可引用公司技能库；
   - 覆盖批准、拒绝、修订、重复飞书事件与缺失输入。

   组织级审批卡的放行顺序固定为：飞书卡片提交决定 → Hermes 转发最小决定信封 → Paperclip 校验并保存决定 → A君 读取审批真相、范围和有效期 → 执行原任务。若 Paperclip 不可用、回写失败或范围不匹配，任务保持 `waiting_governance`，不得落回 `local` 路径。

4. **受限测试实例**
   - 批准后由 A君 准备受限能力配置，Hermes 创建独立 Profile；
   - 测试实例默认最小预算、白名单 Skills/工具、无生产连接；
   - 运行验收任务并把阶段、成本、产物引用回报 Paperclip。

5. **上线与飞书路由**
   - 仅当验收通过才更新为 `active`；
   - 飞书优先使用原生独立 Agent 会话；若不可用，创建官使用明确岗位路由，不能伪装为原生入口；
   - 失败进入 `needs_revision` 并产生安全的下一步。

6. **回归与关闭**
   - 回归小D、Paperclip heartbeat、A君低风险修复和权限拒绝；
   - 外部验收后更新 PRD、验收记录和交接单状态。

## 唯一首个验收案例

选择一个低风险、只读、可用公开素材验证的岗位需求。该岗位必须有一个明确报告类产物，不得要求账号登录、发布、外发、付费或扩权。先以该单例证明闭环，再考虑第二个业务 Agent。

## 停止条件

- Paperclip 招聘审核、A君/Hermes 测试实例或飞书入口任一环节缺少真实可用能力时，停止在该边界，记录证据并不模拟完成；
- 验收任务需要新建飞书应用、改权限、发测试消息或外部账号时，先等待所有者明确授权；
- 预算、审批或产物验证失真时，不继续扩大 Agent 数量。

## 飞书审批分流表

| 请求 | 审批真相 | 飞书表现 | 是否创建 Paperclip 任务 |
| --- | --- | --- | --- |
| 重试已知失败、处理已授权素材、一次性内部发送 | A君 `ApprovalContract` | 原会话审批卡 | 否 |
| 新 Agent、增加 Skill/连接/账号权限 | Paperclip 审批 + A君执行授权 | 原会话审批卡 | 是 |
| 对外发布、付费/预算、跨 Agent 长任务、暂停/终止 | Paperclip 审批 + A君执行授权 | 原会话审批卡 | 是 |

## 当前组织级运行门槛（2026-07-21）

- Paperclip 已以 `ai.agent-army.paperclip` LaunchAgent 常驻，启动命令固定使用 `--no-repair`；`127.0.0.1:3100/health` 已通过。升级或清理 CLI 缓存前，必须先更新并验证启动项。
- 组织级审批卡的放行顺序已实现为“飞书卡片收决定 → Hermes 转发 → Paperclip 保存 approve/reject → A君 复核范围、有效期、会话与幂等键 → 执行或关闭原任务”。任何一步失败都不得降级为 `local`。
- 下一道门槛是手机真实点击后，Paperclip 审批记录和 A君任务状态一致；在该证据出现前，新 Agent、扩权、公开发布、付费、跨 Agent 长任务、暂停/终止仍不算外部验收通过。
