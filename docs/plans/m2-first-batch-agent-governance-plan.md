## 变更契约

- 用户结果：可在飞书提出新岗位需求，并只在审核和验收通过后得到可调用 Agent；
- 不变量：小D直达闭环不被破坏；Paperclip 只管组织级治理；A君只提供本机能力；未批准 Agent 不可运行生产任务；
- 证据：契约/单元测试、Paperclip API 记录、A君/Hermes 测试实例、真实飞书验收和产物验证分别记录；
- 外部边界：创建/发布飞书应用、修改权限、外发、账号登录、扩权和付费动作须重新取得所有者授权。

## 实施切片

1. **治理岗位正式化**
   - 为创建官、架构师、审核官、运维官、协调官补齐 SOP Prompt、输入输出 schema、工具白名单和评测；
   - 运维官新增修复能力前，先在 `LocalCapabilityProviderContract` 登记并限制为 A君自管组件。

2. **草案与审核**
   - 实现 `AgentProposalContract` 存储、版本和状态机；
   - 飞书创建入口只生成草案；
   - Paperclip 适配：草案映射为招聘审核，技能仅可引用公司技能库；
   - 覆盖批准、拒绝、修订、重复飞书事件与缺失输入。

3. **受限测试实例**
   - 批准后由 A君 准备受限能力配置，Hermes 创建独立 Profile；
   - 测试实例默认最小预算、白名单 Skills/工具、无生产连接；
   - 运行验收任务并把阶段、成本、产物引用回报 Paperclip。

4. **上线与飞书路由**
   - 仅当验收通过才更新为 `active`；
   - 飞书优先使用原生独立 Agent 会话；若不可用，创建官使用明确岗位路由，不能伪装为原生入口；
   - 失败进入 `needs_revision` 并产生安全的下一步。

5. **回归与关闭**
   - 回归小D、Paperclip heartbeat、A君低风险修复和权限拒绝；
   - 外部验收后更新 PRD、验收记录和交接单状态。

## 唯一首个验收案例

选择一个低风险、只读、可用公开素材验证的岗位需求。该岗位必须有一个明确报告类产物，不得要求账号登录、发布、外发、付费或扩权。先以该单例证明闭环，再考虑第二个业务 Agent。

## 停止条件

- Paperclip 招聘审核、A君/Hermes 测试实例或飞书入口任一环节缺少真实可用能力时，停止在该边界，记录证据并不模拟完成；
- 验收任务需要新建飞书应用、改权限、发测试消息或外部账号时，先等待所有者明确授权；
- 预算、审批或产物验证失真时，不继续扩大 Agent 数量。
