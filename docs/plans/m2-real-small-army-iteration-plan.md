## 1. 用户最终看到什么

用户主要在飞书中工作。可以直接找某个员工，也可以只找“ A君·军团总管”。A君负责理解需求、分配工作、持续跟进、处理普通故障并主动交付结果。只有登录、花钱、外发、公开发布、删除和扩权等高风险事情需要用户决定。

第一支真实小军团：

1. A君·军团总管：接单、分配、催办、汇总和主动汇报；
2. 小D：处理视频、音频和公开链接；
3. 运维官：发现失败，执行安全重试和本机恢复；
4. 审核官：审核范围、权限和风险；
5. 架构师：从真实工作中发现可复用能力和新岗位机会；
6. 技术专家：接手运维官无法安全恢复的技术问题并实施、验证修复。

创建官和任务协调官作为内部协作岗位保留，不用增加用户每天要面对的选择。

## 2. 什么才算“真实员工”

每个员工必须同时具备：明确职责、可接收任务、允许使用的能力、真实任务记录、执行状态、可验证产物、失败处理和升级对象。只有名称、头像、提示词或一段建议，不算真实员工。

## 3. 迭代顺序

### 第一轮：故障有人接手

```text
业务员工失败
→ 运维官自动接单
→ 安全条件满足时自动重试一次
→ 无法恢复或再次失败，升级技术专家
→ 保留原任务、恢复任务、重试任务和修复任务的关系
```

### 第二轮：总管主动跟进

- 任务完成、失败、等待审批和升级技术专家时，A君主动回到原飞书会话；
- 用户询问“现在怎么样”时，按同一会话返回真实任务链；
- 普通故障不再要求用户输入固定口令才能继续。

### 第三轮：治理员工持续工作

- 运维官定时检查员工和本机能力；
- 审核官为新员工和高风险请求生成真实审查任务；
- 架构师从任务记录中发现高频重复工作，形成新岗位或能力升级草案；
- 技术专家接入受控工程执行器，能修改、测试和恢复项目内允许的本机组件。

### 第四轮：Paperclip 成为真实军团总控

- 组织、岗位、汇报关系、长任务、预算和审计以 Paperclip 为准；
- A君只展示和执行，不复制第二套公司管理后台；
- 用一个跨员工真实任务验证分配、跟进、预算、审批、交付和审计。

### 第五轮：改用飞书官方 Agent 底座

- 飞书官方的收消息、卡片按钮、群内 @ 和原会话回复能力逐步替换 Hermes 安装目录补丁；
- 每个真正在飞书露面的员工先形成最小权限草案，再由负责人扫码创建或更新应用；
- 先验收 A君 + 一位能交付的员工在协作群里的可见接力，不为后台岗位制造空壳机器人；
- 飞书文档、日历、任务等动作优先走官方 CLI，但仍由 A君/Paperclip 判断是否允许和是否需要审批；
- 不引入新的聊天前端，避免和飞书及现有任务记录重复。

## 4. 测试不停工规则

- 能自动验证的，当轮必须运行并记录结果；
- 需要飞书点击、外部平台、登录或人工判断的，登记为“待人工验收”，写明操作和通过标准；
- 外部条件暂时不具备时，登记为“等待外部条件”，继续开发其他不依赖项；
- 一项测试失败只阻止该能力被标记完成，不阻止其他独立能力继续迭代；
- 失败、修复和复测使用同一验收编号，不能删除失败记录来假装通过；
- 唯一验收账本见 [真实小军团验收账本](../reviews/m2-real-small-army/acceptance.md)。

## 5. 安全边界

- 允许自动执行：读取本机脱敏状态、创建任务、一次安全重试、恢复项目自管的低风险本机组件；
- 必须人工决定：登录、验证码、付费、外发、公开发布、删除、扩权和真实账号连接；
- 技术专家已在独立练习和真实 A君 组件故障中实际改对代码、运行测试、做恢复检查，并由 A君安全代为把结果登记回 Paperclip。专家本身不联网，避免把安全边界放开。实际验证发现 Paperclip 的工程副本分配会复用目录或回到主目录，因此不能作为真实修复执行器；A君 负责建立并核验每个任务的唯一副本，范围不清或检查超时则转为待测试，不阻塞其他工作。

## 6. 当前已交付

- 新增真实“技术专家”岗位和本机执行器；
- 任一普通员工执行失败后自动创建运维官恢复任务；
- 可重试故障只自动重试一次，避免无限循环；
- 自动恢复用尽后创建技术专家修复任务；
- 所有任务通过父子关系、恢复次数和固定去重键关联。
- A君与飞书接线会跟进完整任务链，不会在第一次失败后过早结束；成功时交付已确认权限的文档，失败时说明运维官与技术专家的接手情况；
- 审核官会独立检查新岗位草案，并把结论关联到草案和 Paperclip 审批；
- 架构师会读取真实任务记录，只在重复工作达到证据门槛时建议新岗位，不会为了凑人数乱创建员工；
- Paperclip 中已建立技术专家，故障可以登记和分派；受控练习和真实 A君 组件修复都已证明专家能实际修改代码、运行测试、完成恢复检查，A君安全回传后 Paperclip 已保存完整证据；
- Paperclip 的工程副本实测不可靠：不同任务会复用副本，指定目录也可能回到主目录。A君 已接管建立、核验和封存唯一修理副本；真实 A君 组件故障已在该副本中完成修改、测试、回传和安全接回；
- A君已能把安全的“军团盘点”拆给运维官和架构师；Paperclip 真实保存总任务与两项子工作并完成汇总。零预算的真实本机演练已验证“批准前不派活、批准后自动续办”，且子工作不会重复要审批；下一步只剩飞书真人点击同类审批卡；
- 真实本机受控故障演练已通过；真实飞书主动提醒仍记为待人工验收，不阻塞后续开发。
- 任务在自动检查阶段转为“待测试”时，会作为一次明确最终说明回到原聊天：说明当前结果已保留、其他工作继续推进，不无限等待也不冒充修好。真实飞书收消息仍待人工验收。
- 首名公开资料报告员已完成本机真实试用、正式上岗和网页摘要派活；总管的 AI 只能从已上岗员工中选择任务，不能编造岗位或危险能力；所有处理中员工共用原会话最终跟进机制，回复会写明实际完成工作的员工。真实飞书回归仍记为待人工验收。
- 总管收到“帮我判断下一步、安排合适的人”后，会让运维官检查当前运行、让架构师复盘反复出现的工作，并在同一回复中直接交出“当前情况、下一步建议、是否需要你决定”。本机真实入口已验证；真实飞书中的自然说法回归仍记为待人工验收。
- 总管收到“今天军团做了什么、给我工作总结、日报”后，会直接汇总当天真实完成工作、当前推进、待决定事项和待测试数量；内部子工作与技术修理记录只作汇总，不用日志式内容打扰用户。本机真实入口已验证；真实飞书中的自然说法回归仍记为待人工验收。
- A君控制台的日常交办入口只展示负责人真正会用的三类选择：让 A君 判断、小D整理素材、整理公开网页。后台保障岗位仍保留状态可见性，但由 A君 自己调用；页面人工验收已登记为待测试，不能阻塞其他迭代。

- 用户在原飞书会话说“不错/有用”或“不行/需要改进”时，总管会只把评价记到刚完成的那件工作；架构师复盘重复工作时会统计这些评价，优先处理被说“不行”的工作。它不会自动重做、创建新员工或外发；真实飞书验收已登记为 ARMY-022，不能阻塞其他迭代。
- 每件新任务会留下实际运行时长和执行员工明确报告的本机处理次数；“今天花了多少”只汇总执行方实际回传的费用，未回传时明确说不知道，不估算。小D接单、公开网页读取和本机运行检查已接入；真实飞书回归已登记为 ARMY-023，不能阻塞其他迭代。

- 用户在原聊天问“进度”、只说“需要”或“继续”时，总管会直接读取这件工作的真实故障链，明确说明运维官、技术专家或待测试的当前状态；不会再用“正在修复”这类没有对应记录的空话。自动检查已通过，真实飞书受控故障回归仍登记为 ARMY-024，不阻塞其他迭代。
- 对当前没有唯一可执行岗位的陌生目标，AI 会写下目标、最终交付物、缺少材料和安全下一步；它只理解和规划，不会编造员工、任务结果或外部动作。真实飞书回话质量登记为 ARMY-025，不阻塞其他迭代。
