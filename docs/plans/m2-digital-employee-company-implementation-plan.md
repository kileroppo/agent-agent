## 1. 用户结果

老板在飞书把多项工作交给 A君，A君能够分派给小D、资料研究员和办公执行助理；三名员工各自完成真实工作并写回同一任务事实，A君统一交付。老板需要时可以直接找员工，直接入口和总管入口看到同一状态和产物。

## 2. 当前证据

- A君 当前由 Hermes 原生 Gateway 承载飞书连续会话，并通过 Agent Army MCP 读取军团事实；
- 小D 已有独立 Hermes Profile、真实飞书入口和媒体业务闭环；
- `intel-researcher` 已有受控公开研究执行器、独立 Profile、真实模型调用和飞书连续对话；
- 办公执行助理的岗位、执行器、汇报包、独立 Profile、真实模型调用和飞书连续对话均已完成；
- 多人任务已扩展为通用老板总任务，支持最多三项分工、并行、依赖和统一汇报；
- 私人云端办公室与 Mac 工作间的部署包、出站短租约、幂等执行、无 Mac 轻量员工工作、重启恢复和脱敏产物回写已实现并通过隔离运行验收；
- 本机运行台已提供小R和办公执行助理的最小权限接线页，凭据只写私有存储且不回显；模型授权与飞书接线分开显示，已选模型但没有真实凭据调用证据时保持“待授权”；模型授权按钮复用 Hermes 官方 Dashboard，按员工 Profile 深链接并只绑定本机回环地址；
- 创建官、任务协调官、审核官、架构师、运维官和技术专家已各自切换为独立 Hermes Profile Gateway；Paperclip 以 `hermes_local` 唤醒同一身份，岗位 Skill/MCP 由 Manifest 配置脚本生成；
- A君控制台已复用小D通用账号连接管理，展示脱敏连接状态并提供本机撤销；模型授权入口改为根据正式员工 Manifest/Profile 动态解析，后续扩员不再修改硬编码白名单；
- 当前没有可核验的私人云端运行资源，不能把混合在线写成已完成。

## 3. 范围

1. 新增办公执行助理的 Manifest、Prompt、Hermes Profile 映射和本地执行器；
2. 收敛资料研究员为首批真实业务员工，并保留公开只读边界；
3. 扩展直接员工入口，使小D、资料研究员、办公执行助理按岗位接单；
4. 实现 A君 对三项业务工作的统一分派、并行跟进和汇总；
5. 使用父子任务与同一任务编号保持总管/员工入口一致；
6. 使用现有 Agent Army MCP 暴露状态与任务，不复制会话或任务队列；
7. 为三名业务员工准备独立 Hermes Profile，逐一验证后再切换对应飞书入口；
8. 完成自动化、当前运行、真实飞书、重启和审批拒绝验收；
9. 为私人云端办公室准备可部署包；只有拿到实际云主机和费用授权后才进行生产部署。
10. 让六名治理员工都具备独立 Profile、飞书入口、岗位 Skill/MCP 与 Paperclip heartbeat 执行身份；逐个本机验收后再做真实飞书私聊终验。

## 4. 非目标

- 不重写小D媒体执行器；
- 不强迫老板每天面对全部治理岗位；治理员工按需直聊，默认仍可由 A君幕后调度；
- 不新增短期、长期和项目记忆数据库；
- 不复制 Paperclip 组织、预算、审批或调度控制面；
- 不读取、移动或提交任何真实凭据；
- 不在没有云主机、网络和费用证据时声称全天在线已经完成。

## 5. 不变量

- 每名员工使用独立 Profile、岗位 Prompt 和最小工具权限；
- 同一工作只保留一个业务任务 ID，员工执行写回父子任务链；
- 飞书展示不是任务真相；
- 登录、外发、公开发布、付费、删除和扩权必须审批；
- 自动恢复最多一次，不重复已确认外部动作；
- 现有 A君 Hermes 入口、小D入口和六个官方员工回退不因迁移被删除；
- 所有外部入口在真实验收前保持原状态或可回滚。

## 6. 纵向切片

### 切片 A：办公执行助理

`Manifest/Profile → 执行器 → TaskService → A君路由 → 飞书结果呈现 → 单元/运行验证`

交付一个真实、非空、可读的 Markdown 办公汇报包，并记录来源任务与验证结果。

### 切片 B：三员工统筹

`A君多目标输入 → 三个受控子任务 → 独立执行 → 父任务汇总 → 原会话交付`

任何子任务未完成时，父任务不得完整成功。

### 切片 C：员工直聊与同一任务

独立员工入口只创建本岗位任务；带有父任务或任务号的追问必须读取原任务，不新建副本。

### 切片 D：Hermes 独立身份

为资料研究员与办公执行助理准备独立 Profile/MCP/岗位记忆。先用隔离 Profile 验证工具发现、身份、连续对话和重启，再连接真实飞书应用。

### 切片 E：混合在线

已生成私人云端办公室的最小部署包、健康检查、上线前体检和 Mac Worker 安全边界，并完成隔离云端任务的认证、领取、心跳、完成、无 Mac 轻量员工执行和重启恢复验收。实际部署仍需要独立云主机、Google IAP SSH 私有回环通道和费用授权；当前用户选择不部署。

### 切片 F：六名治理员工独立化

`Manifest → 独立 Hermes Home/Profile → 岗位 Skill/MCP → 独立飞书 Gateway → Paperclip hermes_local → 单岗位真实任务`

本机终验已覆盖创建草案、任务分工、权限审核、架构评估、健康证据核对和隔离技术修复。老板随后真实私聊六名员工并收到岗位结果；六个独立 Feishu Session、统一代号命中和创建官跨 Gateway 重启连续追问均由验收器复核通过。过程中发现并修复创建官虚报网页能力以及单员工重配置后 LaunchAgent 未重新注册两个真实缺口。

## 7. 验证门禁

1. Manifest/Profile/契约静态检查；
2. 新执行器与三员工任务的聚焦测试；
3. A君运行时全量测试；
4. 当前 `4321` 运行时加载新代码；
5. Hermes MCP/Profile 隔离验证；
6. 真实飞书单员工、三任务统筹、同任务查询、审批拒绝；
7. Gateway/A君重启后的会话和任务恢复；
8. 文档、链接和秘密形状检查；
9. 云端只有真实部署和关机后飞书证据才可通过。

## 8. 风险与恢复

| 风险 | 处理 |
| --- | --- |
| 当前工作树包含既有未提交改动 | 只追加明确范围，逐文件重读，不提交或覆盖无关内容 |
| 资料研究员注册状态与 Manifest 不一致 | 以真实受限测试和注册记录收敛，未验证前不写正式上岗 |
| 新员工飞书应用需要凭据和发布 | 准备代码/Profile；真实值只写本机私有存储，发布与权限变更按既有授权执行 |
| 多任务重复创建或部分成功 | 父子幂等键、终态汇总和失败测试 |
| 云端资源缺失 | 完成本机闭环与部署包，保留未验证项，不伪造全天在线 |
