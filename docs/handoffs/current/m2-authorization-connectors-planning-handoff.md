## 1. 接手目标

- 目标：交付 A君本地独立运行时，把跨网站/软件登录从各 Agent 的隐式实现中移出；用户不维护内部工具，运行时提供受控、可撤销、可审计的授权连接器。
- 用户约束与不可做事项：不读取、回显、传输或记录密码、Cookie、token、授权 URL、用户标识或私密内容；不绕过验证码、二次验证、访问控制或付费墙；未经明确授权不得连接真实外部账号或外发。
- 做完的定义：一个低风险、已授权读取型平台完成“用户自行授权 → 受限 Agent 调用 → 脱敏审计 → 过期或撤销 → 安全恢复”真实闭环。
- 唯一下一步：由 A 君确认“单一 A君安装包 + 按需浏览器伴侣”的 M2 交付边界，并指定首个低风险、可授权的读取型平台。
- 允许继续的前提：首个平台、账号范围、允许操作和是否可使用浏览器/OAuth 授权入口均获得所有者明确授权。

## 3. 变更与决策

- 已完成：新增 M2 子 PRD；总 PRD 将授权连接器列为 M2 退出条件；系统架构与核心契约明确连接、凭据和任务的真相边界。
- 已完成：调研 `yt-dlp`、MediaCrawlerPro、`web-access`、`agent-reach`、`scout`、`last30days-skill`、AutoCLI 与 bb-browser；M2 PRD 已记录各自的可复用边界。它们只能作为授权网关内部的候选执行器或规则参考，不能向 Agent 暴露浏览器会话或原始凭据。
- 关键文件：`tasks/prd-m2-authorization-connectors.md`、`tasks/prd-agent-army-master.md`、`docs/architecture/system-architecture.md`、`docs/contracts/core-contracts.md`。
- 已确定的边界：业务 Agent 不保存/读取原始凭据；授权连接器只按命名连接与动作授予能力；运维读取健康元数据，审核控制范围与扩权。
- 已确定的首个技术切片：先实现 `ConnectionBroker.execute(connectionId, operation, source)`，在策略校验之后再选择公开媒体、MediaCrawler 或受限浏览器执行器；返回素材引用或脱敏失败，不返回凭据。
- 已确定的产品边界：`yt-dlp`、MediaCrawler、CookieBridge、AutoCLI、bb-browser 等不作为用户需安装和维护的独立软件；它们只能是 A君内部实现候选，进入发行包前仍需许可证、供应链、macOS 兼容性和平台条款审查。用户日常面对 A君.app；需要登录时仅按需启用 A君浏览器伴侣。
- 不要重复创建的产物：不要为每个平台创建保存 Cookie 的独立 Agent；不要在飞书补充输入中请求 Cookie。

## 5. 风险、权限与关闭

- 当前阻塞或风险：首个平台未选；安全存储与授权入口尚未选型和验证；网站可能有验证码、二次验证、地区或付费限制。
- 不得复制或展示的信息：任何凭据、Cookie、token、授权 URL、浏览器会话、用户标识、私密媒体内容。
- 需要谁确认：A 君确认 PRD 和首个平台；审核策略负责人确认读取范围；实施者选择安全存储与授权入口后需架构复核。
- 关闭条件：完成 M2 PRD、契约测试、受控运行时和一个真实低风险连接的完整验收，并同步验收记录与 README。
- 关闭证据链接：待 M2 实施后写入 `docs/reviews/`。
