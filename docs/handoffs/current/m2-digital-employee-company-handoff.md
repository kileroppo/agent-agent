## 1. 接手目标

- 目标：把 A君、业务员工和六名治理员工做成可在飞书分别直聊、也可由总管统一调度的第一支数字员工团队。
- 用户约束与不可做事项：用户不参与实现过程；复用 Hermes/Paperclip/现有 A君；不另造记忆或任务系统；保留现有回退；高风险动作审批；不记录凭据。
- 做完的定义：见验收账本 EMP-001 至 EMP-012。
- 唯一下一步：进入正常业务试用；后续新增员工只需提交符合契约的 active Manifest，再运行治理员工配置器和真实飞书验收命令，不再维护第二份岗位名单。
- 允许继续的前提：保持当前正式工作树既有改动，不覆盖未知变更；不执行付费、公开发布、凭据读取或破坏性迁移。

## 5. 风险、权限与关闭

- 当前阻塞或风险：工作树有既有未提交改动；用户已决定先在本地 Mac 运行，因此 Mac 真关机时整套本地服务不会响应，除非未来另行授权常在线主机。
- Hermes 升级风险：当前上游飞书 WebSocket SDK 使用 INFO 日志级别，可能把带短期连接参数的完整 URL 写入本机 Gateway 日志；本机已改为 WARNING 并完成六 Gateway 重启复验。升级后先检查上游，再按 `integrations/hermes/patches/feishu-ws-log-level-warning.patch` 有条件重放，不能无条件覆盖新版源码。
- 不得复制或展示的信息：任何 App ID、App Secret、token、Cookie、用户/群聊标识和授权链接。
- 需要谁确认：两个飞书应用及本机模型授权已完成；购买云主机、启用云结算或使用新的常在线主机时仍需要老板明确授权。
- 关闭条件：验收账本全部通过，受影响 PRD/架构/契约/README 同步，真实运行与外部证据齐全。
