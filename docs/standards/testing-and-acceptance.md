| 字段 | 内容 |

## 1. 核心原则

- 测试通过证明代码行为，不自动证明当前运行服务加载了新代码；
- 消息发送成功不证明业务完成，关键产物验证才证明交付完成；
- 验证强度按风险决定，小改动不要求完整端到端报告；
- 不使用真实凭据或私人内容制作固定测试夹具；
- 失败必须区分新失败、既有失败、外部平台失败和未验证能力。

## 2. 验证阶梯

1. **静态检查**：语法、契约、schema、lint 或类型检查；
2. **单元测试**：纯逻辑、状态转换、清洗、权限和错误分类；
3. **契约测试**：平台适配器与标准契约的双向映射；
4. **集成测试**：任务从创建到业务产物的完整内部路径；
5. **本地运行验证**：确认监听进程、端口、工作目录、配置来源和接口行为；
6. **真实外部验证**：在授权下验证飞书、Paperclip、Hermes 和真实产物；
7. **人工验收**：负责人确认结果符合业务标准。

每次变更走到与风险相称的最高一级，不机械要求所有任务都走第 7 级。

## 3. 必测内容

### 3.1 领域逻辑

- 正常输入；
- 边界值和空输入；
- 无效来源；
- 状态合法与非法推进；
- 错误分类；
- 产物完整性；
- 权限与审批判断。

### 3.2 长任务

- checkpoint 写入与恢复；
- 进程重启后的继续；
- 最大重试和退避；
- 已完成副作用不重复；
- 取消、过期和等待输入；
- 部分成功不冒充完整成功。

### 3.3 外部适配器

- 正常响应映射；
- 超时、限流、权限拒绝和无效响应；
- 未知字段/状态；
- 日志脱敏；
- 重试和幂等；
- 同步失败补偿。

### 3.4 UI 与飞书交互

- 首次发起；
- 加载和长任务状态；
- 需要补充信息；
- 按需审批；
- 成功交付；
- 可恢复和不可恢复错误；
- 权限不足；
- 桌面与移动端的核心操作可达。

## 4. 小改动验证

不改变工作流、契约和数据的局部改动至少完成：

- 受影响的聚焦测试；
- 必要的语法或静态检查；
- 如影响用户界面，进行对应状态的实际查看。

无需为错别字或链接修复创建独立验收报告。

## 5. 里程碑验收记录

里程碑在 `docs/reviews/<milestone>/` 保存验收记录，至少包含：

- 验收日期与负责人；
- 代码版本或文件快照标识；
- 实际运行目录、进程和端口；
- 使用的入口与任务 ID；
- 已执行的测试和结果；
- 真实场景、结果和产物证据位置；
- 未验证内容、外部阻塞和已知风险；
- 是否满足 PRD 验收标准。

证据不得包含凭据、Cookie、完整私人聊天或无关敏感内容。

## 6. 完成定义

只有同时满足以下条件才可以报告“已完成”：

- 请求范围内的实现或文档已存在；
- 相关自动化检查通过，或失败已明确分类；
- 按风险要求验证了真实运行身份和用户路径；
- 外部能力只有在真实调用后才报告“已验证”；
- 受影响的 PRD、架构、契约、README 和验收状态已经同步；
- 未完成或未验证的部分被明确列出。
