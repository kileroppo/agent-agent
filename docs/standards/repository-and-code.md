| 字段 | 内容 |

## 1. 根目录职责

```text
agent-agent/
├── apps/           正式产品、业务 Agent、按需工具和显式保留的回滚资产
├── agents/         岗位 Manifest、职责、权限和质量标准
├── integrations/   飞书、Paperclip、Hermes 等平台适配器
├── packages/       至少被两个真实消费者复用的公共模块
├── ops/            部署、健康、监控、备份和恢复
├── tasks/          总 PRD、里程碑 PRD 和实施状态
├── docs/           产品、设计、架构、契约、规范和验收记录
├── designs/        可运行的 UI 原型与设计资产
├── repository-catalog.json  Workspace、应用和生命周期机器真相
└── README.md       当前阶段与统一导航入口
```

不在根目录堆放单个应用源码、临时脚本、模型输出或运行产物。

所有根 Workspace 和 `apps/*` 目录必须登记到 `repository-catalog.json`，并由
`npm run check:architecture` 验证路径、包名、入口、用途描述、README 和生命周期。清单损坏、漏登
Workspace、出现未分类应用或把回滚资产重新放入 Workspace 都必须失败。

## 2. 应用目录

每个活动 Workspace 至少包含 `README.md` 和准确的 `package.json#description`。可部署应用还应包含：

- `README.md`：目的、入口、配置、运行、测试、依赖与已知限制；
- `.env.example`：仅列变量名和安全示例；
- 独立依赖清单与锁文件；
- `src/`：应用源码；
- `test/` 或同等测试位置；
- 明确的运行产物目录，并在 README 说明是否应提交。

应用必须能够独立启动和验收。岗位定义放在 `agents/`，不能只藏在应用 Prompt 中。

历史实现只有在仍承担已验证迁移或回滚协议时才可暂留 `apps/`；必须标为 `legacy-rollback`、退出
Workspace、指向正式 replacement，并通过 `ops/` 的唯一受控入口操作。含本机数据库或日志时不得为
追求目录观感直接搬迁；完成数据保留期和恢复演练后再归档到仓库外。

## 3. 分层依赖规则

- 领域逻辑不得直接调用飞书、Paperclip 或 Hermes SDK；
- `integrations/` 可以依赖外部 SDK，但必须输出标准契约；
- `apps/` 通过端口/接口调用集成能力，不读取适配器内部存储；
- `packages/` 不依赖具体应用；
- `ops/` 不包含业务判断；
- UI 展示状态不得成为任务状态真相。

## 4. 何时提取公共模块

只有满足以下条件才进入 `packages/`：

- 至少两个真实消费者；
- 语义和变化节奏基本一致；
- 有明确输入输出与测试；
- 提取后不会迫使业务应用接受无关配置。

仅仅“以后可能复用”不足以提取。

## 5. JavaScript/Node 基线

当前小D使用 Node.js ES Modules，新增代码遵循现有工具链：

- 使用 `import` / `export`，不混用 CommonJS；
- 优先小而明确的纯函数和领域对象；
- 异步副作用必须 `await` 或明确交由受控队列；
- 不吞掉异常；边界层转换为标准错误后再处理；
- 不使用模糊布尔值表达多状态流程，使用明确枚举；
- 时间持久化为 ISO 8601，展示时再本地化；
- 路径使用配置或运行时解析，不把用户机器绝对路径写入业务数据；
- 不新增依赖来解决标准库可以清晰处理的小问题。

格式化与 lint 工具在正式引入前通过 ADR 或小型工具链决策确认；当前不得为了规范重写所有既有代码。

## 6. 命名

- 代码标识符使用英文；用户可见名称和文档可使用中文；
- `agentId`、`taskId` 等稳定 ID 使用小写 kebab-case 或 UUID，项目内保持一种格式；
- 状态、错误码和事件名使用小写英文，禁止多套近义名称；
- 文件名表达职责，不使用 `utils2`、`new-final` 等临时命名；
- 适配器命名包含平台与职责，如 `lark-task-channel`、`paperclip-task-store`。

## 7. 凭据与隐私

- `.env` 不提交；`.env.example` 不含真实值；
- secret、token、Cookie、授权链接不得出现在代码、测试快照、文档和日志；
- 日志只记录排错所需字段，私人内容默认摘要化或使用引用；
- 调试输出在提交前清理或受环境开关控制；
- 任何外发动作必须经过明确接收人和权限检查。

## 8. 错误、重试与幂等

- 错误必须区分可重试、需输入、需人工和永久失败；
- 重试必须有最大次数、退避和安全 checkpoint；
- 写文档、发消息、发布等副作用必须使用幂等键；
- 部分成功保留已完成产物，但不得标记完整成功；
- 用户文案简洁，维护者日志保留真实原因，两者分离。

## 9. 变更边界

小而明确的修复直接实施并测试。以下变化必须先更新设计或 ADR：

- 新增核心平台或持久化技术；
- 改变标准状态、完成定义或数据真相；
- 改变权限、审批或外发边界；
- 迁移历史任务和产物；
- 把单应用能力提取为全军团公共模块。
