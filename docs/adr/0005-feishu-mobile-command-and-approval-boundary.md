# ADR-0005：飞书手机总管与审批分流边界

## 背景

用户需要在任何地点仅通过手机飞书控制 Mac 上的 Agent 军团，不应为了找运维官、提交任务或点一次普通批准而访问 A君局域网页。此前“所有审批均进入 Paperclip”的表述会让一次性、个人范围内的决定多一次中转，并使 Paperclip 变成日常操作前台。

## 决策

- 飞书中的“ A君·军团总管”是唯一日常入口：私聊接收命令，群内只在 @ 提及时接收命令；它只路由、展示进度/结果和发送审批卡，不自行执行业务；
- Hermes Gateway 常驻 Mac，负责飞书收发与运行时路由；Mac 离线时必须给出不可执行或已排队的真实状态；
- 普通一次性审批使用 `ApprovalContract.governanceMode=local`：飞书卡片是界面，A君保存决定并在继续执行前校验范围、有效期和幂等性；
- 只有新 Agent、扩权/账号连接、公开发布、付费/预算、跨 Agent 长任务、暂停/终止或组织级审计使用 `governanceMode=paperclip`；飞书卡片仍是用户界面，Paperclip 是审批真相；
- 不为创建官、架构师、审核官、运维官和协调官分别建设日常飞书机器人。它们由军团总管按任务类型调用。

## 考虑过的方案

### 每个治理 Agent 一个飞书机器人

手机上难以判断该找谁，且会复制身份、会话和权限配置，不采用。

### 所有审批都进入 Paperclip

审计完整，但会使简单批准多一次组织级中转，违背“飞书手机即日常入口”，不采用。

### 所有审批只留在 A君

简单，但新 Agent、长期权限、预算和跨岗位协作缺少组织级追溯，不采用。

### 按治理级别分流

普通一次性决定快而可追溯；改变长期组织能力的决定保留 Paperclip 审计，采用。

## 后果

- 飞书卡片回调必须支持签名/来源校验、幂等、拒绝、过期和补偿；
- A君需要持久化最小审批记录，但不得变成第二个组织级审批中心；
- Paperclip 投影规则、任务契约、验收和图示必须同步按此边界更新；
- 军团总管、`local` 审批卡与本机回调已实现并通过本机验证；真实手机卡片发送/点击、Mac 离线提示和组织级 Paperclip 审批卡仍未完成，不能把本 ADR 当作完整外部能力。

## 落地保护

- Paperclip 暂时不可用不影响已被允许的普通任务和 `local` 审批；它们不应为了“统一记录”被强制中转或阻塞。
- 反过来，命中 `paperclip` 条件的请求不得因为总控离线而改走 A君本地批准。飞书应告知“等待组织级治理恢复”，A君 只保存脱敏等待状态，恢复后重新校验审批范围、有效期和幂等键。
- 组织级飞书卡的正确顺序是“卡片收决定 → Paperclip 保存决定 → A君 二次校验后执行”；卡片本身不是批准依据。
