# ADR-0015：统一主控引擎、自适应调度与三层闭环网关

| 字段 | 内容 |
| --- | --- |
| 状态 | 已接受 |
| 日期 | 2026-08-28 |
| 决策人 | A 君 |
| 修订 | ADR-0001、ADR-0002 中关于 Paperclip 与本地运行时的控制面关系及任务执行阻断策略 |

## 背景

在以往的架构演进中，系统定义了飞书作为交互通道、Paperclip 作为组织总控、Hermes 为执行运行时、A君作为本地能力网关。但在实际业务流转中，存在明显的“各自为政与规则互锁”问题：
1. **控制面双中心与硬阻断**：Paperclip 与 A君 运行时均维护任务状态；当任务被分配给 `executionOwner: 'paperclip-hermes'` 员工（如小D）时，若 Paperclip 未建立 Issue 投影或服务离线，A君执行协调器强行将任务打回 `needs_input`（“这名员工由 Paperclip 唤醒；治理总控恢复前不会改走本地重复执行器”），导致用户在控制台补充信息后进入死循环。
2. **执行权刚性闭锁**：将 Manifest 声明的治理模式作为物理运行的单点阻断，使得本地高可用执行器在治理服务抖动时无法发挥作用。
3. **飞书交互意图过载**：直聊通道缺少前置结构化意图分类，把只读查询（如“查看任务进度#7082B792”）盲目当成岗位转录任务，生成大量缺少链接的畸形垃圾单。

## 决策

### 1. 单一主控引擎与治理镜像分工
- **A君运行时为全系统业务任务的唯一主控引擎**：负责任务生命周期状态机、实时调度、降级自愈与跨渠道（飞书/控制台）交互。
- **Paperclip 为组织治理与审计镜像**：负责维护公司目标、组织树、岗位架构、预算硬限制与异步审计记录。
- **弹性解耦原则**：Paperclip 的在线状态、工单投影或网络连通性**绝不构成业务任务执行与状态流转的同步硬阻断**。Paperclip 在线时异步同步工单与心跳；离线或未就绪时，A君自动以 `local_fallback` 受控本地通道接续执行，并将审计留痕。

### 2. 自适应执行调度（Adaptive Dispatch）
- 调度器根据岗位 Manifest 白名单与可用执行环境（Hermes Profile、本地执行器、专用工作流）动态决策最佳执行路径。
- 不再因为 `executionOwner: 'paperclip-hermes'` 声明而拒绝本地可用执行器的接续调度。

### 3. 统一交互网关三层分流（3-Tier Interaction Gateway）
所有来自飞书、控制台、MCP、API 的交互输入，统一按三层通道分流处理：
1. **Tier 1: 只读查询/状态（Query / Status / Help）**：零副作用，直接返回任务进度卡片或员工工作真相，绝不创建业务新单。
2. **Tier 2: 会话控制/补充输入（Control & Provide Input）**：精准关联目标任务，清除阻塞状态，触发自愈与推进执行。
3. **Tier 3: 业务新任务（Task Intake）**：校验输入完整性与岗位能力契约，完成建单并拉起执行。

## 后果与收益

1. 彻底消除了控制台补充输入后被 Paperclip 硬拦截打回 `needs_input` 的死循环。
2. 彻底消除了飞书直聊中因询问进度而被误建为转录任务的体验缺陷。
3. 飞书、控制台与 Paperclip 之间形成全双向闭环，任何一端的操作均能实时响应、平滑降级与全局对账。
