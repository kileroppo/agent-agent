## 背景

飞书官方资料表明，“一键创建智能体应用”也可用于 Hermes/OpenClaw 接入。此前只观察到一次该应用的测试消息未在小D的安全日志中产生入站标记；事件配置、发布状态、凭据、白名单、运行时路由和日志可见性等原因均未逐项排除，不能把它定性为 Channel SDK 不兼容。

M1 已有 Hermes 的传统飞书机器人 `im.message.receive_v1` WebSocket 适配器，并且已创建独立的传统机器人测试应用。为把首个消息闭环缩小为可控范围，选择它作为 M1 入口。

## 决策

M1 使用独立的传统飞书企业自建机器人应用，名称为“小D · M1机器人测试”。该应用只启用：

- 机器人能力；
- 长连接事件接收；
- 应用身份 `im.message.receive_v1`；
- `im:message` 与读取用户发给机器人的单聊消息所需的最小权限；
- 内部可用，外部群和外部用户单聊关闭。

Hermes 继续使用现有飞书 WebSocket 适配器；小D业务应用、任务契约和产物逻辑不直接依赖飞书 SDK。

## 后果与边界

- 当前一键智能体应用保留为后续集成与单独排障参考，不删除；它不作为 M1 入口是范围选择，不是兼容性结论；
- 针对一键智能体应用的单独验证或任何额外桥接层不纳入 M1，除非后续以独立范围确认；
- 所有者必须在隔离 Profile 手动替换为新传统机器人应用的 App ID、App Secret，并保留获授权用户白名单；
- 新凭据生效并完成“消息入站 → 任务创建 → 飞书回复”验证前，M1 不得标记为完成。
