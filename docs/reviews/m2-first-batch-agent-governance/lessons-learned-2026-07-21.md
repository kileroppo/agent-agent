## 一句话结论

**Agent 接入不能看“页面配置绿了”或“长连接连上了”，只能看一条真实消息是否从用户会话进来、被正确执行、并回到同一会话。**

## 今天确认的坑与固定做法

| 坑 | 今天的实际现象 | 根因或边界 | 以后固定做法 |
| --- | --- | --- |
| 把长连接成功当成机器人可用 | Hermes 显示已连接飞书，但私聊多次没有回复。 | 长连接只证明本机连上飞书，不证明飞书会投递用户消息。 | 新机器人必须完成“私聊入站 → 任务创建 → 同会话回执”三段验收。 |
| 漏掉消息事件订阅 | 独立 A君机器人已发布、权限已开通，但事件列表为空，飞书没有投递消息。 | 单聊读取权限不等于订阅接收消息事件。 | 每次新建或调整机器人都核对：单聊读取权限、`im.message.receive_v1`、版本已发布。三项缺一不可。 |
| 修改后没有重新发布 | 飞书后台显示修改存在，但线上版本仍可能使用旧配置。 | 后台保存与线上生效是两步。 | 权限或事件变更后，确认“当前修改均已发布”，再做真实消息测试。 |
| 复用另一个机器人的用户身份 | 小D与A君属于不同自建应用。 | 飞书的 `open_id` 按应用隔离；同一人也会不同。 | 新应用必须重新配置允许名单、审批人映射、会话关联和幂等键；禁止复制旧应用的用户标识。 |
| 用聊天列表或创建会话替代验收 | 飞书里能看到机器人聊天，但它没有回话。 | 会话存在只证明用户能找到机器人，不证明事件、派发和出站都通。 | 验收账本分为：外部事件投递、Hermes 入站、A君任务状态、飞书回执；每段单独留证。 |
| 只盯一个组件日志 | 网关还会尝试连接其他平台，出现无关失败信息。 | 多平台网关的单个平台错误不能直接解释飞书故障。 | 按目标链路筛选日志；先看飞书事件是否抵达，再看派发与出站，不混入无关平台噪声。 |
| 把配置截图、单测或健康检查说成完整交付 | 自动化和本机健康检查都通过，但真实手机入口曾经不可用。 | 它们证明的是不同层，不可互相替代。 | 报告必须标注：自动化、本机运行、外部平台、人工验收分别是 PASS、PARTIAL 或未测。 |
| 在排障材料里泄露敏感信息 | 飞书与 Hermes 的连接日志可能包含访问参数或身份信息。 | 为追查问题而全量贴日志会扩大泄露面。 | 只保留脱敏的状态、时间、事件名和结果；不记录凭据、用户/会话/任务标识、Cookie、授权链接或原始连接地址。 |
| 创建请求只按固定句式匹配 | “创建一个公开网页摘要 Agent”这类带岗位名称的自然语言请求，没有命中创建路由。 | 路由规则只识别“创建 + 紧邻 Agent”的短句，没有覆盖用户会在中间写岗位名称的正常表达。 | 为每种入口意图保存至少一条真实表达样例；调整路由后，必须覆盖“带岗位名称”“同义动词”和“不应命中”的测试，确认只生成 `draft`，绝不直接激活。 |

## 标准验收清单

1. 飞书后台：机器人能力启用；单聊读取权限已开通；`im.message.receive_v1` 已订阅；修改已发布。
2. 新应用重建允许名单、审批人映射、会话关联和幂等键；不得从其他机器人复制用户身份数据。
3. 本机：确认目标 Hermes 进程使用正确应用配置；重启后已建立飞书连接。
4. 先运行路由测试：低风险检查、带岗位名称的创建请求、小D请求，以及一个不应误判为创建的普通句子。创建请求的预期只能是 `draft` + Paperclip 审核记录。
5. 飞书私聊发送一条无敏感测试命令；依次查 Hermes 入站、A君任务状态、机器人在**同一会话**的回复。
6. 换一个具治理特征的安全测试，再验证是否按规则进入 A君 local 审批或 Paperclip；普通低风险命令不应被错误塞入 Paperclip。
7. 记录自动化、本机运行、外部平台、人工验收四层结论；任一层缺证据只能标为 PARTIAL，不能写“已完成”。

## 排障止损规则

- 没有飞书事件投递或 Hermes 入站证据时，先停在接入层排查；不要改业务 Prompt、任务逻辑或把机器人重建一遍。
- 入站存在但没有 A君任务时，只查路由、输入校验与幂等；不要把问题归因于飞书后台。
- A君任务成功但没有同会话回执时，只查出站接收人类型、会话关联和发送结果；任务成功不等于用户已收到。
- 任何一步出现权限扩大、账号登录、外发、付费或真实业务数据时，停止该测试并走对应审批，不能借“排障”绕过门禁。
