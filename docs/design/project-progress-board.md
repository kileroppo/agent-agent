# 多项目局域网进度看板设计

| 使用范围 | 本人局域网访问 |

## 1. 目标

提供一个多项目共享的 H5 进度看板，用于快速回答：整体规划到哪里、当前在做什么、哪些已经完成、哪些尚未开始、哪些被阻塞，以及下一步该做什么。

看板是项目进度的主要维护入口；PRD、项目文档和 Git 状态作为关联依据与参考，不自动把技术活动推断为业务完成。

## 2. 页面结构

### 项目总览

- 顶部展示项目数、总体完成度、进行中任务、阻塞任务和最近更新时间。
- “当前重点”优先展示进行中与阻塞任务。
- 项目列表展示项目状态、当前阶段、完成度、当前任务和更新时间。
- 整体规划按阶段展示待做、进行中和已完成数量。
- 提供新建项目入口。

### 项目详情

- 顶部展示项目状态、完成百分比、当前阶段和下一步动作。
- 主体由阶段时间线和任务看板组成。
- 任务看板分为未开始、进行中、已完成、阻塞四组，支持直接变更状态。

### 任务详情

展示任务名称、状态、进度、负责人、截止时间、下一步、阻塞原因、备注，以及 PRD、文档和 Git 链接。

## 3. 状态与进度规则

- 任务状态为：未开始、进行中、已完成、阻塞。
- 只有明确标记为“已完成”的任务计入完成度。
- 阻塞任务单独统计，不混入普通进行中任务。
- 项目进度按任务状态计算，同时允许手动修正并记录原因。
- 项目和阶段均可设置规划日期，但日期不强制决定状态。

## 4. 数据与运行边界

- 第一版使用本机 SQLite 保存项目、阶段和任务数据。
- H5 通过本机服务提供，局域网设备使用浏览器访问。
- 文档和 Git 以链接或轻量同步信息关联，不引入账号、权限、云端同步和复杂协作。
- 后续可增加 Markdown 文档读取、Git 状态刷新和局域网只读分享。

## 5. 验收标准

- 打开首页即可看到所有项目和总体进度。
- 能区分未开始、进行中、已完成和阻塞任务。
- 能从总览进入项目详情，再进入任务详情。
- 新增或更新任务后，项目进度和统计立即同步。
- 局域网另一台设备可以打开并查看看板。
- 页面在手机宽度下不出现关键内容横向溢出。
- Git 或文档信息缺失时，看板仍能正常使用。

## 6. 决策记录

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 产品范围 | 多项目共享 | 满足长期管理多个项目的需要 |
| 维护方式 | 看板手动维护，文档/Git 辅助 | 进度真相由项目状态决定，避免错误推断 |
| 页面形态 | 总览为主，项目内局部 Kanban | 同时满足全局规划和任务操作 |
| 运行方式 | 本机服务 + 局域网访问 | 低成本、低权限、适合本人使用 |
| 持久化 | SQLite | 比 JSON 更适合查询、更新和后续扩展 |
| 第一版边界 | 不做登录、权限、云端协作 | 控制复杂度，先证明进度闭环 |
