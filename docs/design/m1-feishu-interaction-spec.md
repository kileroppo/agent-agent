## 1. 交互原则

- 一张任务卡片只突出一个主要动作；
- 不显示无法由真实数据支撑的百分比；
- 状态消息按关键阶段合并，避免刷屏；
- 反馈紧邻相关任务，不依赖全局通知；
- 技术信息默认折叠，但始终可追溯；
- 成功以产物可访问为准。

## 2. 卡片信息结构

```text
状态标签 + 任务标题
一句当前说明
必要的阶段/风险/错误摘要
主要操作
次要入口：任务详情
任务 ID · 更新时间
```

任务标题优先使用来源标题；尚未解析时使用“正在识别视频信息”。不在卡片标题堆叠 Agent 名称、平台名和技术栈。

## 3. 状态设计

| 用户状态 | 标题示例 | 主要操作 | 次要操作 |
| --- | --- | --- | --- |
| 已接收 | 已接收转录整理任务 | 查看任务详情 | 取消任务 |
| 处理中 | 正在转录音视频 | 无强制按钮 | 查看任务详情 |
| 需要补充 | 需要确认处理方式 | 提交补充信息 | 取消任务 |
| 待审批 | 是否发送给外部联系人？ | 批准并继续 | 拒绝、查看详情 |
| 交付中 | 正在创建并验证飞书文档 | 无强制按钮 | 查看任务详情 |
| 已完成 | 文档已创建并验证权限 | 打开飞书文档 | 下载原始转录、查看详情 |
| 可恢复失败 | 转录在中途暂停 | 继续任务 | 查看原因、取消任务 |
| 永久失败 | 当前来源无法访问 | 修改来源 | 查看授权说明 |

## 4. 阶段文案

阶段文案使用真实动作：

- 正在获取素材；
- 正在转录音频；
- 正在整理文章结构；
- 正在生成原始转录与整理稿；
- 正在创建并验证飞书文档。

禁止使用“AI 正在思考”“马上就好”“已完成 80%”等无法验证的模糊文案。

## 5. 提交交互

- 用户可以直接粘贴链接并发送；
- 默认任务要求为“保留原意，输出原始转录与中文整理稿”；
- 更多选项不在首轮弹出，只有来源或要求存在歧义时再询问；
- 发送后立即回显用户消息，系统创建成功后再返回任务 ID；
- 创建失败时保留输入，允许直接重试。

## 6. 补充信息

每次只询问阻止任务继续的最关键问题。例如：

> 这个链接包含多个视频。请选择要处理的范围。

主操作使用明确动词，如“处理当前视频”或“全部处理”，不使用“确定”。如果选择会显著增加成本，需要同时显示估算范围。

## 7. 审批卡片

审批卡片必须显示：

- 将要执行的动作；
- 目标接收人或数据范围；
- 触发审批的风险原因；
- 批准有效期；
- 批准与拒绝两个互斥动作。

批准按钮不得默认代表永久授权。拒绝后保留安全产物，并告诉用户任务停在何处。

## 8. 成功交付

成功卡片默认展示：

- 文档标题；
- 一句结果摘要；
- “打开飞书文档”主按钮；
- 原始转录入口；
- 来源、权限已验证和任务 ID 的简短状态。

文档预览只展示足够识别结果的片段，不在聊天卡片复制整篇内容。

## 9. 错误与恢复

- 用户文案说明发生了什么和下一步；
- 维护者详情保留错误码、失败阶段、尝试次数和日志引用；
- 可恢复失败显示“继续任务”；
- 永久失败不显示无效重试；
- 重试不会重复已完成文档或通知；
- 平台同步失败不应错误描述为转录失败。

## 10. 视觉语言

- 使用飞书语境的浅灰背景、白色内容面和蓝色主动作；
- 成功使用低饱和绿色，待审批使用橙色，错误使用红色；
- 不使用渐变、装饰性大阴影或多层嵌套卡片；
- 正文采用系统中英文字体；
- 通过间距、字号和对齐建立层级，不用大段解释占据首屏；
- 图标只辅助识别，不用表情符号替代产品图标。

## 11. 原型评审门禁

进入飞书集成编码前需要确认：

- 主流程和七种关键状态是否完整；
- 每个状态的主要动作是否唯一且正确；
- 普通任务是否没有被审批打断；
- 成功交付是否以产物为中心；
- 桌面与移动宽度下核心操作是否可达；
- 原型中的组件能否映射到当前飞书真实能力。
