## 目标体验

用户在任何地点只用手机飞书控制 Mac 上的 Agent：下任务、查看真实状态、收到交付、批准或拒绝有影响的动作。用户不需要知道治理 Agent 的名字，也不需要进入 A君局域网页。

## 唯一入口

- 用户私聊“ A君·军团总管”直接下令；
- 用户在群内以 `@A君` 下令；
- 军团总管将命令路由给小D、运维官、创建官或其他已启用岗位；
- 进度、补充问题、审批卡和最终交付均回到原飞书会话；
- Mac 不在线时明确返回“不可执行”或“已排队”，不得伪造执行中。

## 三条首批命令

| 用户说什么 | 路由 | 结果 |
| --- | --- | --- |
| “整理这个视频” | 小D | 飞书文档/附件或可恢复失败说明 |
| “检查系统状态” | 运维官 → A君 | 脱敏健康摘要和安全下一步 |
| “创建一个 XX Agent” | 创建官 → 架构师/审核官 | 草案摘要；后续只在通过测试后上线 |

## 审批流程

### 普通一次性审批

```text
执行任务暂停
→ 飞书原会话审批卡
→ 用户批准 / 拒绝
→ A君记录 local ApprovalContract 并校验范围、有效期、幂等性
→ Hermes 继续 / 取消 Mac 上的任务
→ 飞书回结果
```

例子：重试已知失败、处理已授权素材、一次性内部发送。此路径不创建 Paperclip 任务。

### 组织级审批

```text
执行任务或创建草案触发组织级条件
→ Paperclip 创建或关联任务与审批真相
→ 飞书原会话审批卡
→ 用户批准 / 拒绝
→ A君校验 Paperclip 决定与范围
→ Hermes 继续 / 取消 Mac 上的任务
→ 飞书回结果
```

例子：新 Agent、增加 Skill/连接/账号权限、公开发布、付费/预算、跨 Agent 长任务、暂停/终止。用户始终只点飞书卡；Paperclip 是后台档案柜。

## 不做什么

- 不让用户为每个治理 Agent 找不同飞书机器人；
- 不把 A君网页作为日常派活或审批入口；
- 不让普通任务为了留痕而经过 Paperclip；
- 不让飞书卡片直接授予永久权限或绕过 A君的二次校验。
