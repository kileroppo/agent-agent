# 上下文、记忆与成本治理

| 字段 | 内容 |
| --- | --- |
| 状态 | 源码生效；历史清理和 Hermes Profile 写入保持显式发布 |
| 版本 | v1.1 |
| 最后更新 | 2026-08-16 |

这套治理只解决一件事：让模型看到完成当前工作所需的最小事实，不把所有聊天、过程和 Agent 输出无脑带入下一轮。

## 1. 四个边界

| 层 | 保存什么 | 不保存什么 |
| --- | --- | --- |
| 当前任务上下文 | 目标、已采纳产物、关键决定、未完成项、唯一下一步 | 原始聊天、完整日志、网页正文、产物正文 |
| Hermes Session | 当前会话的最近上下文；压缩时保护首 3 段和末 8 段 | 组织级任务真相、长期任务副本 |
| 跨任务记忆 | 负责人明确要求记住、会长期复用的偏好或规则 | 单次任务结果、Agent 过程、临时资料 |
| A君/Paperclip 账本 | 任务状态、审批、产物引用、审计事件 | secret、Cookie、Prompt 原文和不必要的聊天正文 |

## 2. 任务上下文胶囊

`TaskContextCapsule` 是从任务真相生成的只读投影，不是第二套存储。字段固定为：

- 目标与结果摘要；
- 最多 10 个已验证产物引用；
- 最多 5 条关键决定和 5 条未完成项；
- 一个明确下一步；
- 最多 10 个证据引用和更新时间。

胶囊会脱敏并限制长度，不携带产物正文、原始进程输出或凭据。架构快照只保留最近 24 条任务证据；Hermes 压缩策略只保护最近 8 段上下文。

## 3. 模型调用预算

活动岗位的预算来自 Manifest，并由 Profile 配置器投影给 Hermes：

| 岗位 | 最大轮次 | 推理强度 |
| --- | ---: | --- |
| 运维官 | 8 | none |
| 小D、小办 | 12 | low |
| A君 | 20 | low |
| 小R、小拆、小创、创建官、审核官、架构师、技术专家 | 16 | medium |

全部岗位的 API 自动重试最多 1 次，并开启工具循环硬停止。后台员工执行默认在服务端最多等待 240 秒，超时后的再次查询间隔为 30 秒，避免把等待过程变成反复模型调用。

## 4. 记忆准入

只有负责人明确要求记住，且内容会跨任务复用时，才允许写跨任务记忆。只有当前请求明确提到“之前、上次、继续”等历史指代时，才允许检索会话历史，并最多读取 3 段摘要。

Hermes Profile 关闭自动记忆提示，记忆写入需要确认。任务成果进入任务账本和产物引用，不复制到每个 Agent 的长期记忆。

## 5. 运行事件分级留存

| 等级 | 默认期限 | 示例 |
| --- | ---: | --- |
| `transient` | 7 天 | 开始、进度、轮询、普通阶段变化 |
| `detail` | 30 天 | 常规执行详情和诊断元数据 |
| `audit` | 365 天 | 审批、费用、回执、产物提交、完成与审核结论 |
| `permanent` | 永久 | 必须长期保留的脱敏事故摘要 |

删除故障事件前会先合并生成永久脱敏事故摘要。旧数据库启动时只迁移约束和值，不删除事件。

历史清理默认是 `dry-run`。只有明确设置 `AGENT_ARMY_EVENT_RETENTION_MODE=apply` 才执行删除；发布前必须先核对预览计数和事故摘要。

## 6. 发布与观测

Hermes Profile 同步必须先执行：

```bash
node apps/ajun-runtime/scripts/configure-governance-hermes-runtime.mjs --dry-run
```

核对每个 Profile 的差异、30 天 Session 清理预览和回滚输入后，才可显式改用 `--apply`。源码合并不代表 live Profile 已写入或运行服务已重启。

账单视图额外暴露：按任务/系统/独立会话/未归属划分的输入 Token、记忆写入次数、历史检索次数和预算硬停次数。首轮验收目标是与基线相比输入 Token 降低 30%、模型调用次数降低 20%，并保持业务验收通过率不下降；这些是发布后的观测目标，不是源码测试可以证明的结果。

## 7. Provider 总账与账外调用

成本事实必须分成三层，禁止相互冒充：

1. 任务用量记录：只证明某个受管任务主动回报的调用；
2. Hermes 用量账本：只证明本机受管 Profile 的会话累计用量；
3. Provider 账户总账：证明同一账号、同一时间窗内所有密钥和客户端的总量。

没有第 3 层时，运行台必须显示“尚未核对 Provider 总账”，即使本机账本是 0 次也不能显示“账号没有调用”或“成本正常”。Provider 总量回填后，系统计算 `Provider - 受管账本` 的调用与 Token 差额；正差记为账外调用，不伪造任务流水。

受管调用的运行事件记录任务、岗位、Provider、模型、凭据别名、调用类型、输入/输出/缓存/推理 Token、Provider 尝试和限流次数。事件只允许保存凭据别名和哈希，不保存真实密钥、Prompt、请求正文或响应正文。显式的 `model_call_*` 事件缺少归属字段时拒绝落库。

真正阻止其他程序绕过账本，需要把 StepFun 凭据收口到统一模型网关并停用共享直连密钥。仓库已有选型结论优先复用 LiteLLM Proxy 的虚拟密钥、按用户/团队计费、预算、TPM/RPM 和并发限制；源码候选不等于已安装或 live 生效。安装 Postgres、设置主密钥、轮换 StepFun 密钥、改写 Hermes/Paperclip Base URL 和重启服务都属于外部依赖、凭据与运行态变更，必须单独授权并按 dry-run → 小流量 → 全量顺序执行。
