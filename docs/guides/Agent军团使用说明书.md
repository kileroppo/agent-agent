# Agent军团使用说明书

> 面向第一次接触 Agent军团的使用者。看完后应能判断该找谁、发什么、会收到什么，以及何时必须人工介入。

## 先看这里

日常只需要记住一句话：**不知道找谁就飞书找 A君；知道岗位时，可直接私聊有独立飞书入口的员工。**

说明书已于 2026-08-07 接入当前 4321 不可变运行版和 11 个 Hermes Profile。每个岗位的当前问答内容以自身 `manifest.json` 中的 `userManual` 为准；本文档是便于集中阅读的长版。

现在可以这样问：

- 问 A君：`把所有 Agent 的使用说明书发给我`，A君会查询全部已上岗岗位；也可以问 `小D怎么用？` 获取单个岗位。
- 问小D、小R、小办、运维官等独立员工：`你的使用说明书是什么？`，它会查询并回答自己的当前说明书。
- 独立员工不能代答其他岗位；查询别人的说明书会提示去问 A君。
- 说明书问答不会创建业务任务，也不会触发登录、外发、模型付费或其他执行动作。

### 使用前提

- 系统维护者已经完成 Hermes Profile、飞书 Bot、Paperclip 与本机运行服务的接线。
- 使用者的飞书账号在允许范围内。普通使用者不需要安装 Codex、Hermes 或飞书 CLI。
- 涉及登录、私密数据、外发、公开发布、付费、删除或扩权时，必须等待明确审批。
- Mac 关机或本机服务未运行时，本机岗位不能工作。

### 各工具到底负责什么

- **飞书 Bot / 飞书接入层**：接收任务、补充信息、显示审批卡、把结果送回原会话。它是使用入口，不负责判断任务是否真的完成。
- **Hermes**：承载每名员工的独立 Profile、会话、记忆、模型与工具选择。
- **Paperclip**：管理组织级任务、负责人、依赖、heartbeat、预算、审批和审计。简单单人任务不一定经过 Paperclip。
- **A君本地运行时**：提供任务路由、受控本机工具、健康检查、产物登记和安全恢复。
- **Codex**：只在技术专家的隔离代码修复和系统维护中按授权使用，不是所有 Agent 的默认运行时。
- **飞书 CLI / lark 工具**：由系统接入层用于创建文档、验证权限或交付；普通使用者不需要自己运行命令。

### 关于“省了多少时间”

当前仓库能证明部分真实任务的系统处理时间，但没有为所有岗位建立“人工原耗时”的三次对照样本。下面凡写“待采样”，都表示不能把估算当成宣传数字。

截至 2026-08-07 的仓库任务快照中，最近一次成功样例从任务创建到终态分别为：小D约 1 分 39 秒、小R GitHub 检索约 1 秒、小办固定 4 页 PPT 样例约 12 秒、运维健康检查约 8 秒、小拆约 2 分 38 秒、小创约 1 分 1 秒、创建官约 50 秒、审核官约 1 分 11 秒、架构师约 2 分 23 秒、技术专家受控练习约 1 分 12 秒、A君内容选题任务约 12 秒。这些数字是特定本机样例，不是飞书端到端 SLA，也不能直接等同于节省的人工时间。

对外发布量化结果前，建议每个岗位记录至少 3 次：`人工开始时间 → 人工可用产物时间` 与 `发送任务时间 → Agent 可用产物时间`，再使用中位数。

## A君·军团总管

### 它是什么

这是军团的统一任务入口：把一句自然语言目标整理成任务，安排已上岗员工，跟进进度，并把真实结果或卡点送回原聊天。

### 省了什么人工

- 之前：负责人自己判断找谁、逐个派活、追进度、汇总结果。
- 现在：把目标、材料、限制和完成标准一次告诉 A君，由它路由和跟进。
- 量化：跨岗位人工节省尚未建立对照样本；最近一次受控内容选题任务约 12 秒完成，不代表复杂多人任务耗时。

### 用了什么工具

- Hermes：承载 A君的独立会话、记忆、模型和工具选择。
- Paperclip：记录跨岗位、长任务、预算、审批和审计。
- A君本地运行时：读取真实员工/任务状态，创建任务或多人 Mission。
- 飞书 Bot：接单、追问、审批和交付。

### 输入

- 目标：一句话说明想得到什么结果。
- 材料：链接、文件或已有任务引用。
- 限制：是否只读、是否允许外发、预算和截止时间。
- 完成标准：什么产物算可用。

### 如何触发

在飞书找到 **A君·军团总管**，私聊直接发送；群聊必须真实 `@A君`。

```text
目标：把这条公开视频整理成中文重点，并做一页汇报。
材料：[公开 URL]
限制：只读，不登录，不发布。
完成标准：给我整理稿、来源和一页汇报；做不了的地方明确写出。
```

也可以追问：`现在谁在做？哪里卡住？`、`停止当前任务`、`把这个补充作为下一步单独处理`。

### 输出示例

真实输出会包含：承接员工、任务短号、当前状态、产物入口、未完成项和一个下一步。仓库任务快照中，A君任务 `605b7988-fa26-4c2e-84ce-c4cfd01fdd26` 以 `succeeded` 结束并登记 2 个产物引用。

### 成功运行截图

仓库目前保留任务与验收记录，没有提交可公开复用的 A君飞书对话截图。正式对外说明书应补拍一张“用户发目标 → A君说明分工 → 最终交付”的同一飞书会话截图，并遮挡人员、会话和内部任务敏感信息。真实验收记录见 [M2 小军团验收](../reviews/m2-real-small-army/acceptance.md)。

### 圈友怎么用

1. 让系统维护者把你的飞书账号加入允许范围。
2. 找到 A君 Bot，按“目标、材料、限制、完成标准”发送。
3. 收到补充问题时直接在原会话回答。
4. 高风险操作只在范围明确的审批卡中决定。
5. 最终检查产物，而不是只看“已完成”字样。

### 注意事项

- A君不会代替专业员工虚构产物，也不会把草案员工说成已上岗。
- 登录、外发、付费、删除、扩权和公开发布必须人工批准。
- 服务健康不等于业务任务成功；应检查最终产物和未决项。
- 超出当前岗位能力时，A君应说明缺口，而不是静默猜测。

## 小D·音视频转录整理专员

### 它是什么

这是一个音视频转录与证据整理 Agent，把已获授权的公开链接或本地媒体变成原始转录、质量报告、确认稿、可读整理稿和交付结果。

### 省了什么人工

- 之前：获取素材、提取字幕或音轨、转录、检查完整性、整理、创建飞书文档、验证权限并分享。
- 现在：发送一个获授权的链接或文件，小D自动跑完可自动完成的阶段；检测到低置信度或硬完整性问题时再找人听审。
- 量化：竞品说明书的“2 小时 → 10 分钟”可作为待验证基准，不能当成本系统实测。仓库最近成功样例约 1 分 39 秒，但素材仅约 49 秒，不能外推到长播客。

### 用了什么工具

- Hermes：承载小D Profile、会话、记忆与 Skills。
- 内容获取中心、yt-dlp / ffmpeg 与平台适配器：获取字幕、音轨或本地媒体；不绕过登录和访问控制。
- faster-whisper / mlx-whisper / 本地 ASR：语音转文字。
- 小D证据链：保存不可覆盖机器稿、来源证据、质量报告、确认记录和校验值。
- 飞书接入层：创建文档、检查接收权限、把链接送回原会话。
- Paperclip：仅在长任务、跨岗位或组织级治理需要时记录任务。

### 输入

- 公开音视频 URL：系统已支持的平台公开链接；平台能力以当前内容获取中心为准。
- 已授权平台素材：必须先由账号连接管理完成范围授权，不能把 Cookie 或 Token 发给小D。
- 本地媒体：系统允许目录内的音频或视频文件，如 MP3、M4A、WAV、MP4。
- 可选要求：`只要整理稿`、`保留时间点`、`需要完整人工听审`、`同时提取关键帧`。

### 如何触发

直接私聊小D Bot，或在 A君中提出任务。

```text
请转录并整理这个公开视频：[URL]
要求：保留原始转录和来源证据；输出中文分段整理稿；术语不确定处标出来；不要发布。
```

如需人工完整听审，明确写：`这份内容会用于正式创作，请等待我完整听审确认后再交给下游。`

### 输出示例

真实任务 `c0636161-cb44-4449-81ee-9baa4e027570` 生成 7 类产物：来源证据、机器原始转录、转录质量报告、任务交付记录、17 帧/2 组故事板、系统质量确认记录和带校验值的确认稿。该样例为本地交付，`larkUrl=null`，不能把它说成飞书文档交付；历史真实飞书交付证据见 [M2 授权与内容获取验收](../reviews/m2-authorization-connectors/acceptance.md)。

### 成功运行截图

仓库未保存可公开复用的“小D对话 + 飞书文档”截图。对外使用时应补拍两张：第一张包含任务发起、处理状态和最终文档链接；第二张打开文档，展示标题、分段整理、来源和质量说明。不要拍到 App Secret、内部路径、Cookie、Token 或用户标识。

### 圈友怎么用

1. 找到已接通的小D Bot；没有独立入口时找 A君。
2. 发送链接或上传系统允许范围内的媒体文件。
3. 说明输出语言、用途、是否要时间点和是否需要完整听审。
4. 等待小D返回整理稿或补充问题。
5. 正式使用前检查人名、术语、数字和低置信度标记。

如需在自己的环境重新搭建，先完成 [Hermes Agent 与飞书 Bot 接线](./创建Hermes-Agent与飞书Bot接线教程.md)，再按小D应用 README 安装业务执行器；“Bot 能回复”不等于转录闭环已经上线。

### 注意事项

- 不能绕过登录、付费、地区限制或来源访问控制。
- ASR 可能错听人名、术语和数字；重要内容需要人工校对。
- 低置信度、音轨缺尾或覆盖不完整会停下，不能靠人工点击绕过硬完整性失败。
- 未明确批准时不能外发或公开发布。
- 不要在聊天、文档或日志中粘贴 App Secret、Cookie、Token。

## 小R·公开情报研究员

### 它是什么

这是一个公开资料研究 Agent，读取无需登录的网页、PDF 和 GitHub，输出带来源、证据边界和行动建议的中文报告。

### 省了什么人工

- 之前：自己搜索、打开多条来源、摘录、去重、比较并写报告。
- 现在：给出问题、范围和交付格式，小R完成公开来源读取与结构化整理。
- 量化：人工基线待采样；最近一次 3 个 GitHub 项目的元数据检索样例约 1 秒，只代表检索，不代表深度研究。

### 用了什么工具

- Hermes：独立研究会话、记忆、模型和 Skills。
- 公开网页搜索/读取、动态网页只读、PDF 读取和 GitHub 公开检索适配器。
- Paperclip：长研究、跨岗位或需要审计时登记任务和产物。
- 飞书 Bot：直接接单和交付报告。

### 输入

- 研究问题：要回答什么，不要只给一个宽泛关键词。
- 来源范围：指定 URL、指定站点，或允许小R自行搜索公开来源。
- 时间范围与排除项：例如只看近一年，不读付费内容。
- 输出要求：摘要、比较表、结论、建议、未决问题。

### 如何触发

直接私聊小R Bot，或找 A君转派。

```text
请研究“多 Agent 编排产品的治理能力”。
范围：公开官网、官方文档和公开 GitHub；不登录、不读付费内容。
输出：3 个候选、能力差异、适用场景、来源链接和仍未证明的地方。
```

### 输出示例

真实任务 `5c485f4b-8b2a-4ef1-8ad1-02a5eeca496c` 以关键词 `agent orchestration` 返回 3 个公开 GitHub 项目，包含项目名、描述、Stars、语言、更新时间、URL、基于本次元数据的评估和边界说明。更完整的飞书研究闭环见 [数字员工公司验收](../reviews/m2-digital-employee-company/acceptance.md)。

### 成功运行截图

仓库未提交可公开使用的小R飞书报告截图。补拍时应同时展示：用户问题、至少两个可点击来源、结论和“未证明”边界；只截搜索结果列表不能证明研究报告完成。

### 圈友怎么用

1. 明确要解决的问题、来源范围和输出形式。
2. 发送给小R或 A君。
3. 小R要求补范围时，在原会话补充，不要重开相同任务。
4. 收到报告后随机打开至少两条来源，核对结论是否有依据。

### 注意事项

- 只读取公开、无需登录的内容；私密、付费或账号内资料需要另走授权流程。
- GitHub Stars、更新时间和单页信息只是线索，不等于产品能力或商业效果。
- 来源不足时应返回“不足以判断”，不会用常识补成事实。
- 不负责外发、购买、发布或修改外部系统。

## 小办·办公执行助理

### 它是什么

这是一个办公交付 Agent，把负责人提供的材料和其他员工的真实产物整理成汇报包、Markdown、DOCX、XLSX、PDF、PPTD 或 PPTX。

### 省了什么人工

- 之前：收集多人结果、核对完成状态、排版、做表格/幻灯片、导出并逐项检查。
- 现在：给出材料引用、受众和交付格式，小办生成受控文件并执行结构与回读检查。
- 量化：人工基线待采样；2026-08-07 固定 4 页 PPT 样例从创建到成功约 12 秒，真实业务稿仍取决于材料量和人工审阅。

### 用了什么工具

- Hermes：理解办公目标、组织材料和生成结构。
- 本地 DOCX、XLSX、PDF、PPTD/PPTX 工具链：写文件、回读、重算、渲染和结构质检。
- A君本地运行时：限定工作区、登记产物和质量状态。
- Paperclip：引用任务真相和登记 Work Product。
- 飞书 Bot：接收要求并交付文件或摘要。

### 输入

- 当前任务材料，或明确引用的其他员工任务/产物。
- 受众与用途：老板汇报、项目周报、执行清单或演示。
- 交付格式：Markdown、DOCX、XLSX、PDF、PPTD、PPTX。
- 模板、页数、截止时间和必须出现的结论。

### 如何触发

直接私聊小办 Bot，或找 A君转派。

```text
请把任务 [任务短号] 的真实结果整理成 4 页项目汇报 PPTX。
受众：项目负责人。
必须包含：目标、完成项、风险、下一步。
限制：只使用已存在的产物，不补造数据；本地生成，不发送外部编辑器。
```

### 输出示例

真实任务 `ca1c34a8-f58f-48ff-a86b-c1a1e06ea5a8` 生成可编辑 PPTD、结构/视觉 QA 和 4 页 PPTX 三类产物；PPTX 完成 ZIP/XML、逐页渲染、4 个 fade 和无溢出检查。详细证据和文件位置见 [小办演示文稿能力验收](../reviews/office-presentation-capability/acceptance.md)。

### 成功运行截图

固定样例的 WPS 逐页截图已存在于本机验收目录 `~/.agent-army/toolchains/local-pptx/1.0.0/verification-20260807T045722Z/work-products/smoke/presentation/qa/wps/`，但尚未复制到仓库的公开说明书资产中。对外发布前应挑选一张无敏感内容的总览截图，并注明这是固定样例还是业务任务。

### 圈友怎么用

1. 把材料上传到任务，或给出已有任务/产物短号。
2. 说明受众、用途、格式和页数，不要只说“做得高级一点”。
3. 小办返回文件后，打开原生办公软件检查字体、分页、图表和可编辑性。
4. 对外发送仍需人工确认接收人和版本。

### 注意事项

- 不会编造其他员工尚未产出的结果。
- PPTX 字体未嵌入时依赖目标机器的兼容字体；目前已在 WPS 验证，未声称 Microsoft PowerPoint 全部兼容。
- 自动结构/渲染检查不能替代最终业务内容审阅。
- 外发、公开发布、删除和扩大权限需要审批。

## 运维官

### 它是什么

这是一个本机健康与安全恢复 Agent，读取脱敏状态，发现异常时只做白名单内的一次受限恢复，仍失败就升级给技术专家。

### 省了什么人工

- 之前：人工逐个检查进程、端口、任务和连接，再判断能否安全重试。
- 现在：运维官按登记目标自动检查并给出组件状态、证据、恢复动作和升级对象。
- 量化：人工基线待采样；最近一次健康检查约 8 秒并生成 2 个产物。

### 用了什么工具

- 确定性本机健康探针：检查登记的 HTTP 服务、契约和依赖，不调用模型猜状态。
- A君本地运行时：执行白名单安全恢复和故障升级。
- Paperclip：记录巡检、Issue、恢复和审计。
- Hermes / 飞书 Bot：处理人工发起的健康问题并返回中文报告。

### 输入

- 默认输入：`检查军团现在有没有问题`。
- 可选范围：指定 A君、小D、Paperclip 或某个任务短号。
- 故障上下文：发生时间、用户看到的错误和是否允许一次安全重试。

### 如何触发

直接私聊运维官 Bot，或对 A君说：

```text
请让运维官检查 A君、小D 和 Paperclip 当前健康状态。
只读检查；仅允许登记过的安全恢复，不要登录、扩权或重启未知服务。
```

健康例行巡检也可由 Paperclip Routine 定时触发。

### 输出示例

真实任务 `3a799143-764c-4481-8699-0175650464dd` 返回本地健康报告：A君 `127.0.0.1:4321/api/overview`、小D `127.0.0.1:4318/api/health` 与 Paperclip 均为 healthy，并记录 HTTP 状态、延迟、契约是否满足和“无需恢复动作”。

### 成功运行截图

仓库保留机器可读健康报告和验收记录，没有提交可公开的飞书截图。补拍时应展示检查时间、组件、证据和恢复动作；只截三个绿色图标不足以证明检查有效。历史验收见 [M2 小军团验收](../reviews/m2-real-small-army/acceptance.md)。

### 圈友怎么用

1. 出现故障先把时间、任务短号和用户看到的现象发给运维官或 A君。
2. 不要先发送密钥、完整日志或自行授权扩大范围。
3. 看报告中的“证据”和“下一步”，不是只看 healthy/failed。
4. 运维官升级技术专家后，继续使用原任务链跟进。

### 注意事项

- “服务能打开”不等于业务任务已经交付。
- 不读取密钥、不代登录、不处理验证码、不重启未知外部服务。
- 没有足够证据时会写 `待测试`，不会冒充修好。
- 高风险恢复、外部变更和权限扩大需要人工批准。

## 小拆·视频内容拆解师

### 它是什么

这是一个基于证据的视频分析 Agent，复用小D的确认稿、来源元数据和关键帧，输出带时间点与画面引用的结构拆解或表现复盘。

### 省了什么人工

- 之前：反复看视频、记时间点、截关键帧、拆结构、整理成报告。
- 现在：小D先生成可追溯证据，小拆再完成 fast 或 full 拆解。
- 量化：人工基线待采样；最近一次成功 full 样例约 2 分 38 秒。岗位硬上限为 fast 5 分钟、full 12 分钟，超限会交付部分结果而不是继续消耗。

### 用了什么工具

- Hermes：执行岗位分析和证据约束。
- 小D内容包：提供确认稿、来源、时间点、关键帧和故事板。
- `agent-army-video-content` 与本地视频/视觉能力：生成 13 模块分析和画面证据。

- 小D确认稿任务短号或产物引用。
- 分析深度：`fast` 或 `full`。
- 分析目标：内容结构、开场、节奏、画面、可复用模式或发布后复盘。
- 可选表现数据：必须带来源和可比较基线。

### 如何触发

小拆没有独立飞书入口。对 A君说：

```text
请让小拆基于小D任务 [任务短号] 做 full 视频拆解。
重点：开场、信息推进、情绪转折、镜头与字幕配合、可复用结构。
每项判断要引用时间点或关键帧；不预测播放量。
```

真实任务 `4f8b55ca-8c53-4f48-aeb5-95bf1165b60a` 基于系统确认稿、17 帧和 2 组故事板，生成 complete 的 13 模块 full 拆解；结论绑定来源片段、时间点和帧 ID。完整验收见 [M3 内容增长验收](../reviews/m3-content-growth/acceptance.md)。

- 不直接下载、登录平台或绕过内容获取中心。
- 没有基线时不能把表现差异写成因果结论。
- 不负责发布、私信或扩大账号权限。

## 小创·内容创作师

### 它是什么

这是一个有证据约束的内容创作 Agent，基于确认稿、正式拆解和受控参考案例，生成待人工审核的脚本、平台草稿或生产包。

### 省了什么人工

- 之前：从素材找角度、写标题、脚本、镜头、字幕和发布前检查表。
- 现在：把确认稿、正式拆解、主题和平台交给小创，获得最多三个平台的待审版本或五文件脚本生产包。
- 量化：人工基线待采样；最近一次成功平台草稿样例约 1 分 1 秒。岗位默认最多两次尝试、5 分钟，超限停止并交付部分结果。

### 用了什么工具

- Hermes：组织创作简报、平台表达和质量门禁。
- 小D与小拆产物读取：只读当前任务引用的确认稿和正式拆解。
- 受控公开搜索：事实型主题缺来源时最多读取少量公开网页。
- 本地图片、图片编辑和语音能力：只在当前任务已批准和对应阶段使用。
- Paperclip / A君：按需唤醒、登记草稿、检查外部副作用。

### 输入

- 小D确认稿任务短号。
- 小拆正式报告任务短号，或受控参考案例。
- 新主题、目标受众、平台、时长和品牌语气。
- 不能说什么、必须保留什么，以及审核标准。

### 如何触发

小创没有独立飞书入口。对 A君说：

```text
请让小创基于确认稿 [短号] 和正式拆解 [短号]，
为“家庭关系里不要把试探当沟通”生成一版 45 秒抖音可拍脚本。
只复用结构，不复制原案例人物和台词；输出标题、完整口播、镜头、字幕、来源和发布前检查表；不要发布。
```

真实任务 `a5415600-1a4e-41e9-8779-655cbd69e058` 生成 35 秒抖音职场短剧待审稿，含 3 个标题、完整台词/节奏、5 条来源证据和 6 项人工检查；状态明确为 `draft_only`、外部副作用为 0。详见 [M3 内容增长验收](../reviews/m3-content-growth/acceptance.md)。

- 不自行抓取账号内容、读取 Cookie、发布、私信或投流。

## 创建官

### 它是什么

这是一个 Agent 岗位设计助手，把“我需要一个能做 X 的员工”整理成包含职责、边界、能力、预算和验收任务的 `AgentProposal` 草案。

### 省了什么人工

- 之前：手工写岗位卡、权限边界、预算、验收任务，再逐项交审核。
- 现在：用自然语言描述需求，创建官生成可审核草案并提交治理流程。
- 量化：人工基线待采样；最近一次成功草案约 50 秒。它只完成草案，不包含审核、测试和上岗时间。

### 用了什么工具

- Hermes：把自然语言需求收敛成结构化岗位草案。
- Paperclip：登记 `AgentProposal`、审核、受限测试和激活状态。
- A君本地运行时：读取现有员工和已登记能力，避免重复造岗位。

### 输入

- 想解决的重复工作与当前人工流程。
- 允许输入、期望输出和成功标准。
- 明确禁止动作、数据范围、预算和审批人。
- 一个无敏感数据的最小验收任务。

### 如何触发

创建官没有独立飞书入口。对 A君说：

```text
我需要一个“只读网页差异核对员”。
输入：两个公开 URL。
输出：文本和结构差异报告。
限制：只允许 GET，不登录、不截图、不修改网页、不外发。
请先生成草案和最小验收任务，不要直接上线。
```

### 输出示例

真实任务 `268ca021-f2cd-426f-9aa3-8358221b7e39` 生成“只读网页差异核对员”草案，包含岗位目标、职责、非职责、唯一任务类型、能力、预算、验收标准、待审核原因和边界声明；没有创建真实员工或扩大权限。

### 成功运行截图

仓库未提交可公开的创建流程截图。补拍时应形成三张连续证据：A君收到需求、Paperclip 中出现 `draft/pending_approval` 草案、草案详情明确写“未上线”。

### 圈友怎么用

1. 先确认这是稳定、重复、可验收的工作，而不是一次性杂事。
2. 把人工流程、输入、输出、禁区和验收任务发给 A君。
3. 审阅创建官草案，重点看权限和不做什么。
4. 只有审核、受限测试和负责人批准都通过后，才允许上岗。

### 注意事项

- 草案不是员工，上线前不能承接生产任务。
- 创建官不会安装 Skill、创建账号连接或授予权限。
- 发现本机已有 Skill 只表示可考虑复用，不表示已安全可用。
- 涉及私密数据、登录、外写和付费必须单独审批。

## 审核官

### 它是什么

这是一个风险与范围审核 Agent，在负责人决定前检查目标、数据、工具、预算、有效期、外部副作用和交付条件。

### 省了什么人工

- 之前：负责人从长草案中手工查权限、预算、风险和缺失信息。
- 现在：审核官先给出“可决定 / 需补充 / 应拒绝”的结构化建议，负责人只做最终决定。
- 量化：人工基线待采样；最近一次成功治理审核约 1 分 11 秒。

### 用了什么工具

- Hermes：按岗位规则阅读脱敏审批材料并生成审核结论。
- Paperclip：读取任务与审批元数据，保存审核和负责人最终决定。
- 本地视觉能力：仅在内容机器审核任务和批准范围内检查画面，不读取凭据。

### 输入

- 动作目标与申请人。
- 数据、账号、工具、预算、有效期和影响范围。
- 预期产物、质量门和失败处理。
- 明确的最终决定人。

### 如何触发

通常由创建官或高风险任务自动进入审核官；也可对 A君说：

```text
请让审核官检查这份 Agent 草案是否可以进入受限测试。
重点核对：数据范围、工具白名单、预算、有效期、外部副作用和失败停机条件。
审核官只给建议，最终由我决定。
```

### 输出示例

真实任务 `032c6f94-3539-409a-8631-5b9c3ff89fcf` 对微信聊天取件员草案给出“可进入负责人决定：批准一次受限合成测试”，逐项核对数据范围、工具、预算、有效期、外部副作用和验收门禁，并明确“合成通过不等于上岗或真实聊天授权”。

### 成功运行截图

仓库未提交可公开的审核卡截图。补拍时应包含审核对象、建议结论、风险、有效期、缺失信息和负责人按钮；不能只截“通过”两个字。

### 圈友怎么用

1. 提交结构完整的申请，不要让审核官替你猜范围。
2. 阅读它列出的风险和缺失信息。
3. 信息不足时先补材料；不要强行点批准。
4. 最终由有权限的人在范围明确的审批卡或 Paperclip 中决定。

### 注意事项

- 审核官不替负责人做最终敏感授权。
- 审核通过不等于目标动作已经执行，也不等于产物质量最终通过。
- 不读取 Secret、私密原文或浏览器会话。
- 批准必须有范围和有效期，不能把一次批准永久复用。

## 架构师

### 它是什么

这是一个系统能力评估 Agent，根据真实岗位、任务和仓库证据，判断现有能力能否完成目标、结构性缺口在哪里，以及最小验证应该先做什么。

### 省了什么人工

- 之前：人工翻岗位、任务、工具和历史问题，再区分是路由问题、能力缺口还是需要新员工。
- 现在：给出问题与约束，架构师分开陈述当前事实、架构判断和未来候选方案。
- 量化：人工基线待采样；最近一次成功架构审查约 2 分 23 秒。

### 用了什么工具

- Hermes：完成分析、假设和候选方案表达。
- A君岗位注册表与任务真相：提供当前员工、任务类型、工具和受控证据。
- Paperclip：承接架构审查任务、记录候选方案和后续验证任务。

### 输入

- 想实现的业务目标和当前症状。
- 已知任务短号、岗位或失败记录。
- 这次允许改变和明确不改变的边界。
- 希望得到的是评估、候选方案还是最小实验。

### 如何触发

架构师没有独立飞书入口。对 A君说：

```text
请让架构师判断：目前军团能不能稳定完成“内容机器审核”？
只依据当前 Manifest、工具和最近任务；区分事实、判断和候选方案。
先给最小验证，不要安装工具、扩权或新建员工。
```

### 输出示例

真实任务 `371caaa4-72e1-4f8c-b3a4-6de22a241e7d` 判断一次高周转的根因是任务路由与工具能力不匹配，而不是审核官效率问题；报告列出事实引用、假设、置信度、止血方案、长期候选和验证计划。

### 成功运行截图

仓库未提交可公开的架构师飞书截图。补拍时应展示“当前事实 / 架构判断 / 候选方案 / 最小验证”四部分；只有方案图不能证明它基于当前系统。

### 圈友怎么用

1. 给出真实目标、症状和已有任务短号。
2. 明确哪些边界本轮不能动。
3. 要求架构师引用当前岗位或任务证据。
4. 先执行最小验证，再决定是否改架构或新增岗位。

### 注意事项

- 候选方案不是已实现能力。
- 架构师不直接装工具、接账号、扩权或上线新岗位。
- 没有真实证据时应明确写未知项。
- 优先复用现有平台和适配器，不复制 Paperclip 等控制面。

## 技术专家

### 它是什么

这是一个受控工程修复 Agent，接手运维官无法安全恢复的技术故障，先分类和限定范围，再在隔离工作区内修改、测试和恢复检查。

### 省了什么人工

- 之前：人工读故障、建立隔离副本、定位、改代码、跑测试、检查恢复并登记证据。
- 现在：在允许文件、测试命令和恢复标准都明确后，技术专家调用隔离 Codex 修复执行器完成受控闭环。
- 量化：人工基线待采样；最近一次成功受控练习约 1 分 12 秒。真实复杂故障不能按此估算。

### 用了什么工具

- Hermes：读取 Paperclip 指派、完成故障分类和判断是否具备修复条件。
- Paperclip：保存原故障、修复任务、审批、Run 和证据。
- A君隔离修复工作区：建立按任务隔离的副本、校验允许路径和回带条件。
- Codex：只在已批准的文件范围内修改代码、运行指定测试和恢复检查。

### 输入

- 原故障任务短号和脱敏错误。
- 允许修改的精确文件。
- 必须运行的测试命令。
- 恢复检查与仍需人工验证的外部部分。

### 如何触发

通常由运维官自动升级。也可对 A君说：

```text
请把故障 [任务短号] 升级给技术专家。
允许修改：[精确文件]
测试命令：[命令]
恢复标准：[可验证结果]
不得读取 Secret、修改其他文件或直接操作生产外部系统。
```

缺少允许文件、测试命令或恢复检查时，技术专家不会开始代码修改。

### 输出示例

真实任务 `8b86db66-f123-4e6d-ba21-0df68016d762` 在隔离副本中只修改练习文件 `calculator.mjs`，运行 1 项测试并通过，验证 `add(2,3)=5` 与 `add(-1,1)=0`，随后才安全带回；任务登记 3 类证据产物。详见 [数字员工公司验收](../reviews/m2-digital-employee-company/acceptance.md)。

### 成功运行截图

仓库没有提交可公开的技术修复流程截图。补拍时应展示原故障、允许范围、修改文件、测试结果、恢复检查和剩余风险；不要截完整终端环境变量或私密日志。

### 圈友怎么用

1. 先让运维官形成脱敏故障和升级关系。
2. 由维护者明确允许文件、测试和恢复标准。
3. 等技术专家在隔离工作区完成，不要让它直接改 live 目录。
4. 分开检查代码测试、本机恢复、外部平台和人工验收。

### 注意事项

- 没有完整修复范围时只做诊断，不执行修改。
- 不读取或回显凭据，不绕过登录和审批。
- 测试通过不等于外部系统或真实用户路径已恢复。
- 主工作区存在冲突修改时应保留冲突，不覆盖用户工作。

## 微信聊天取件员（高敏感按需能力）

### 它是什么

这是一个只读本机微信 Vault 的私密资料助手，在负责人批准的单一会话和时间范围内读取消息，仅用本机模型生成不含聊天原文和发送者标识的摘要、决定、待办、风险或回复建议。

### 省了什么人工

- 之前：人工在长群聊中翻找决定、待办和遗漏事项。
- 现在：指定联系人或群和时间范围，批准一次临时读取后得到结构化结果。
- 量化：人工基线和真实任务耗时待采样；已验证一次 6 条消息的真实只读链路，但不能外推到 200 条上限。

### 用了什么工具

- `yichen-wechat-local-vault` 受控只读适配器：只取本次批准的会话切片。
- 本机 Qwen3.5-9B：原文只在本机内存和回环模型中处理。
- A君临时授权：绑定 Agent、任务、会话、时间、条数、有效期和使用次数。

不会把私密原文发送给 DeepSeek、Paperclip、飞书或其他外部模型/平台。

### 输入

- 一个联系人或群名。
- 可选时间范围；默认今天至现在。
- 可选条数；默认最多 200 条。
- 想得到的结果：摘要、决定、待办、风险或回复建议。

### 如何触发

没有独立飞书入口。对 A君说：

```text
读取今天“项目推进群”的聊天，最多 200 条。
只输出决定、负责人、待办、风险和回复建议，不要返回聊天原文或发送者标识。
```

系统会先展示本次隐私范围，只确认一次。批准后临时授权默认 30 分钟、最多 10 次，可撤销。

### 输出示例

输出结构为：范围说明、主题摘要、已决定事项、待办、风险、建议回复和隐私边界。真实验收曾在负责人明确授权后读取指定群 6 条消息，原文未持久化；证据边界见 [M3 内容增长验收](../reviews/m3-content-growth/acceptance.md) 的微信 Vault 记录。

### 成功运行截图

私密聊天原文不应进入说明书截图。可公开截图只能展示已脱敏的授权范围、成功状态和结构化输出标题，并遮挡联系人/群名、成员、消息和本机路径。

### 圈友怎么用

1. 先让系统维护者在本机初始化 Vault；不要把数据库、密钥或 salt 发到聊天。
2. 告诉 A君一个联系人或群和时间范围。
3. 核对授权卡中的会话、时间、条数、有效期和用途后再批准。
4. 检查输出是否含原文或发送者标识；若有，立即停止并报告。
5. 用完可让 A君撤销临时授权。

### 注意事项

- 不发送微信消息，不后台常驻监控，不读取未批准的其他会话。
- 原文不落盘、不进云模型、不进 Paperclip、不进飞书交付。
- 本机 Vault 或本地模型不可用时会停止，不降级到云端。
- 每次新会话或扩大时间范围都需要新的明确授权。
