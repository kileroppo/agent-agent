## 1. 目标

完成第一批可控 Agent 军团闭环：小D作为现有业务 Agent；创建官、架构师、审核官、运维官、任务协调官作为受限治理 Agent；用户只需在飞书“ A君·军团总管”会话中描述需求，Mac 上的 Hermes/A君 路由并执行。普通任务和一次性审批在飞书+A君闭环；新 Agent、扩权、外发、花钱、跨 Agent 长任务才进入 Paperclip。新岗位经 Paperclip 审核、A君/Hermes 受限测试和真实验收后上线。

## 2. 用户流程

```text
飞书“ A君·军团总管”："创建一个 XX Agent，产出 YY"
→ 协调官识别为创建请求，交给创建官
→ 创建官生成 AgentProposal 草案
→ 架构师检查复用、边界和验收任务
→ 审核官提出权限/预算审核意见
→ Paperclip 批准、拒绝或要求修改
→ 批准后建立 draft 测试实例
→ A君 准备本机能力，Hermes 建立隔离 Profile
→ 运维官检查健康，运行一条白名单验收任务
→ 通过：active 并允许飞书路由；失败：needs_revision
```

## 3. 第一批范围

| 对象 | 第一批职责 | 不做什么 |
| --- | --- | --- |
| 小D | 飞书媒体/链接整理与交付 | 因创建流程重写既有业务闭环 |
| 创建官 | 从一句需求生成 AgentProposal | 直接创建生产 Agent 或授予权限 |
| 架构师 | 复用检查、边界和验收建议 | 自动创建 Agent/Skill/适配器 |
| 审核官 | 权限、预算和外部动作审核意见 | 代替负责人最终批准 |
| 运维官 | 脱敏健康、低风险 A君 修复、升级故障 | 登录、扩权、读取凭据或重启未知服务 |
| 协调官 | 复杂任务的拆分与路由建议 | 拦截简单小D任务 |
| 飞书军团总管 | 唯一手机入口：接住命令、展示状态/结果、发送审批卡 | 自己执行业务、保存任务真相、绕过治理门禁 |
| Paperclip | 招聘审核、组织级任务、预算、审批、审计 | 处理媒体、保存业务 checkpoint、替代 Hermes |
| A君 | 本机能力、测试实例、连接/健康/恢复 | 第二个组织或任务总控 |

## 4. 强制门禁

- 一句需求只能生成 `draft` 草案；不允许直接 `active`；
- Skills 只能从已审核公司技能库选择；新增 Skill、外部连接、发布、外发、付费和扩权必须单列审批；
- 测试实例默认隔离、最小预算、白名单工具和无生产账号；
- 草案必须有可验证产物和一条验收任务；
- 真实飞书调用成功且产物通过质量门禁，才可上线；首名公开资料报告员已完成本机试用、真实飞书调用和原会话交付；
- 未通过时保留证据并进入 `needs_revision`，不得伪造上线。
- 普通一次性审批只授予本次任务、所列范围和有效期内的动作；由飞书审批卡与 A君审批记录闭环，不创建 Paperclip 投影。
- 新 Agent、权限扩展、账号连接、公开发布、付费/预算、跨 Agent 长任务、暂停/终止或组织级审计，必须创建或关联 Paperclip 投影；飞书卡片只是手机上的决策界面。

## 5. 验收标准

1. 用户能在飞书私聊“ A君·军团总管”，或在群内 @ 它，发起一条创建岗位需求并收到草案摘要；
2. 草案包含 `AgentProposalContract` 所有必填字段，且不含凭据或私密内容；
3. Paperclip 中可看到审核、预算、决定人与状态；
4. 只有批准草案可创建隔离测试实例；
5. 测试实例只能调用被批准的 A君能力和 Skills；
6. 一条白名单验收任务产生可验证产物；
7. 通过后可从飞书调用新 Agent；失败/拒绝时不可路由为正式 Agent；
8. 小D既有飞书业务闭环回归通过。
9. 用户在手机飞书可发起“小D处理素材”“检查系统状态”“创建 Agent”三类命令；协调官分别路由给小D、运维官、创建官，且不要求打开 A君网页。
10. 一次性审批由飞书卡片批准/拒绝后，A君只在范围与有效期内继续任务；普通审批不创建 Paperclip 任务。
11. 命中组织级条件的审批在同一张飞书卡片完成决定，但 Paperclip 可查询审批、范围、决定人和最终状态。
12. Paperclip 不可用时，普通任务与 `local` 审批仍按既有飞书 → Hermes → A君 边界运行；所有命中组织级条件的任务必须停在“等待治理”，不得降级为 A君 本地批准或绕过执行。

## 6. 默认非功能约束

- 初期仅服务一位负责人和少量内部协作者；同一时间最多一个 Agent 创建测试实例；
- 创建请求、审核、测试和上线都必须有稳定 ID、幂等键、状态与审计记录；
- 所有草案、运行时日志和审批记录不得包含 secret、Cookie、token、浏览器会话或不必要的私人内容；
- 任何外部写入、账号连接、扩权、付费或公开发布默认关闭，须单独重新授权；
- 测试实例失败必须可停止、可删除其测试状态、可保留脱敏证据；不得影响小D或已上线 Agent；
- A君本机能力与 Paperclip/飞书的可用性应分别报告，单一健康检查不代表整个创建闭环完成。
- 组织级审批卡只能在 Paperclip 当前可访问、审批范围可读、决定可回写时放行；否则飞书只展示“等待治理恢复”，不伪造批准。

## 7. 决策记录

| 决策 | 备选 | 选择理由 |
| --- | --- | --- |
| 日常入口 | 多个 Agent 机器人、A君页面、一个飞书军团总管 | 一个飞书总管降低手机端找人的成本；它只路由，不自己执行 |
| 审批归属 | 所有审批进入 Paperclip、所有审批只在本机、按治理级别分流 | 普通一次性批准走飞书+A君；会改变组织能力或需要长期审计的批准才进入 Paperclip |
| 创建结果 | 直接生产上线、仅文档草案、草案到受限测试再上线 | 兼顾“言出法随”与权限/质量门禁 |
| 治理 Agent | 常驻自由聊天、事件触发受限 SOP | 治理职责依赖证据与边界，不应拥有全盘权限 |
| 首个新岗位 | 任意平台自动化、公开只读报告类岗位 | 无外部账号与副作用，最适合证明链路 |
| 飞书新入口 | 假设可动态创建原生侧栏、原生优先并允许路由过渡 | 飞书租户实际能力尚未验证 |

## 8. 非目标

- 不支持一句需求自动上线任意生产 Agent；
- 不建设 Agent 商城、开放模板市场或多租户 SaaS；
- 不自动读取浏览器会话、账号、Cookie、token 或私密媒体；
- 不在第一批实现任意 Skill 生成、任意适配器生成或自我扩编；
- 不要求为每个治理 Agent 创建独立飞书机器人或原生侧栏入口；由一个飞书军团总管路由即可。
