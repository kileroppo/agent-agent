## 1. 本切片目标

建立一条可信的内容增长流水线：

```text
内容获取中心
→ 小D生成原始转录、来源证据和质量报告
→ 质量合格时系统自动确认；异常或明确要求时转人工听审
→ 小拆生成证据化拆解
→ 小创生成最多三个平台的待审草稿
→ 真人决定是否发布
→ 小拆基于真实指标复盘
→ 小办写入统一知识库
```

本切片正式增加两个后台按需岗位：

- `video-content-analyst`：小拆·视频内容拆解师；
- `content-creator`：小创·内容创作师。

同时升级小D的转录证据链，并扩展小办的受限知识归档能力。两个岗位均已上岗并完成真实 Paperclip/Hermes 运行；`BV1GM796EENj` 已在本机跑通图文拆解、抖音待审草稿和 Obsidian 归档，旧链路也已有真实飞书与人工听审证据。负责人于 2026-07-30 确认已在 2026-07-29 完成新版内容质量判断和最终飞书脚本闭环，本切片与 M3 里程碑完成验收。

## 2. 范围

### 2.1 小D转录证据链

- 保留不可静默覆盖的机器原始转录；
- 生成来源证据、转录质量报告和内容校验值；
- 音频覆盖不足、尾部缺失等硬门禁不能由人工确认绕过；
- 默认由质量门禁自动确认；通过后直接生成版本化 `confirmed_transcript` 和 `automatic_transcript_attestation`，明确记录 `confirmationMode=automatic`、`completeListen=false`；
- 转录异常、硬门禁失败或用户明确要求人工听审时进入 `waiting_approval`；人工确认后生成 `human_review_attestation`，明确记录 `confirmationMode=human`、`completeListen=true`；
- 自动确认不能冒充人工听审；两种确认稿都保留机器稿校验值、确认方式和版本关系。
- ASR 选择对用户透明：可靠来源字幕继续优先；质量模型是当前 Mac 的默认主路。备用小模型只有在主模型失败且任务不是正式/完整分析时才能降级接管，降级稿必须转人工完整听审；不得只按时长选择，也不得因备用模型返回高置信度就自动确认。

### 2.2 小拆

- 任务类型：
  - `content.video-benchmark-analysis`
  - `content.performance-review`
- `content.video-benchmark-analysis` 支持 `visualMode: auto|off|required`，默认 `auto`；快速模式最多 12 帧，完整模式最多 48 帧，每张故事板最多 12 帧；
- 小D按来源和用途经内容获取中心分别获取字幕/音轨与视频：B站优先原生字幕，非B站不得调用B站字幕技能，本地上传直接复用本地视频；
- 小D从开头、场景变化、字幕重点和均匀时间点选帧，过滤近似重复画面，生成带可见时间戳、校验值和选择原因的 `visual_evidence_package`；
- 本地 ASR 同时保留 TXT、VTT 和 JSON 时间轴；原生字幕已有时间点时直接复用，不重复 ASR；
- 来源证据记录真实原标题、作者、平台、时长和脱敏标准链接；标题优先级固定为“内容包真实标题 → 用户标题 → 本地文件名”，缺失字段不编造；
- `fast` 输出 5 个模块，最长 5 分钟、最多 2 次尝试；
- `full` 输出完整 13 模块，最长 12 分钟、仅允许一次安全重试；视觉提取与 Hermes 分析共享该预算；
- 只有 URL 且没有既有转录任务时，A君必须自动建立“小D受控获取/转录确认 → 小拆分析”的同一总任务；URL 只交给小D，业务岗位不得绕过 `ContentAcquisitionCenter`；
- 正式分析只接受 `confirmed_transcript`；机器稿只能生成明确降级的初步分析；
- 每个判断关联时间点或来源片段；没有时间点时降低证据等级；
- 画面判断必须关联关键帧和时间点；视觉结论融入既有模块，不新增平行章节；
- 报告记录 `sourceMetadata`、`visualCoverage`、`visualFindings` 和 `completeness`；`auto` 取不到视频时交付 `partial` 文字稿，`required` 取不到视频时进入 `needs_input`；
- 真实表现复盘必须同时引用原拆解、原草稿和结构化真实指标，不声称确定因果。

### 2.3 小创

- 任务类型：`content.platform-draft`、`content.video-script-package`；
- 只读取系统或人工确认稿和正式拆解报告；
- 一次最多生成三个平台版本；
- 产物包含标题候选、开场、正文或脚本、节奏、平台适配、来源证据和发布前人工检查清单；
- 只生成草稿，不直接发布、私信、登录、投流或扩大账号权限；
- 不承诺固定播放量、转化率或“百万播放”。
- 用户只给主题时，系统自动选择平台、时长和一项主要参考结构；默认抖音竖屏约 45 秒，不要求用户选择模板；
- 参考视频先作为案例；只有用户回复“用这版”后才成为 `trial` 模板。至少使用三次、其中至少两次达到账号基准且基准样本不少于五条时才标记 `validated`；连续三次低于基准时标记 `retired`；
- 匹配顺序为用户指定案例、`validated`、`trial`、相似正式案例、通用结构；无匹配时自动降级，不向用户暴露模板 ID、评分和文件目录；
- 事实型主题缺少来源时自动读取最多三个公开网页；读取失败时改写为不依赖外部事实的观点或方法，不编造；
- `video_script_package` 内部固定包含 `script.md`、`shots.json`、`subtitles.srt`、`sources.md` 和 `manifest.json`，默认只向用户展示一版可读脚本和一个下一步；
- 生产包只供后续成片工具消费；当前不生成成片、不发布。

### 2.4 小办知识归档

- 新任务类型：`office.knowledge-summary`；
- 输入只允许当前任务的脱敏正文、明确引用的 `taskId`/产物，以及 A君生成的受限会话快照；
- 通过 Auto-work `content_system_runtime.py` 解析统一内容库根目录；
- 只写入 `Agent军团/` 逻辑目录，不接受任意文件路径，不读取私人笔记；
- 文件名为“日期 + 标题 slug + taskId 短标识”，相同幂等键返回原文件，重名产生新版本；
- 返回受控文件引用、SHA-256、字节数和回读验证结果。

## 4. 契约和权限

- 保持 `TaskContract`、`ArtifactContract`、`ContentPackage` 顶层结构不变；
- 新增任务类型和产物类型登记见[核心契约](../docs/contracts/core-contracts.md)；
- 小拆、小创不建立独立飞书 Gateway，由 A君接收、路由和交付；
- 用户不需要学习任务类型、模板状态或文件结构；A君用自然语言接收“按这个结构写一个关于……”和“用这版”；
- 两个新岗位必须按 `draft → pending_approval → testing → active` 完成治理；
- 小拆只获得引用产物读取和分析产物写入；小创只获得确认稿/正式分析读取和草稿写入；
- 小办不获得 Vault 全盘读取、私人笔记搜索或任意路径写入；
- 不新增任务队列、审批系统、账号系统或控制台。

## 5. 非目标

- 自动发布、自动私信、自动投流或绕过平台登录；
- 把未确认机器稿用于正式创作；
- 将 ChatGPT Web、微信数据库或平台 Cookie 作为核心依赖；
- 复制 Paperclip、内容获取中心或统一账号管家的控制面；
- 用测试通过、模型返回或文件存在冒充真实飞书和人工质量验收。

## 6. 验收

### 6.1 自动化

- Manifest、Hermes Profile、任务路由和工具作用域一致；
- 已有转录产物时不重复获取；
- 正式/初步分析、5/13 模块、证据关联、预算停止均有测试；
- 小创拒绝机器稿、拒绝初步分析、拒绝超过三个平台；
- 只给主题时自动匹配参考案例并生成五件生产包；默认回复不展示 JSON、模板状态和五个内部文件；
- “用这版”只升级为 `trial`，不生成成片、不发布；真实指标满足门槛后才能进入 `validated`，连续低于基准会进入 `retired`；
- Whisper 置信信号异常时不得自动确认转录，即使音频覆盖完整；
- ASR 路由覆盖字幕绕过、当前机器性能策略、质量模型失败时的低风险降级、正式任务拒绝降级，以及备用稿强制人工听审；
- 知识归档通过路径、幂等、重名、脱敏、不可覆盖和回读校验；
- 未批准的外部研究拒绝；微信本地 Vault 草案可登记但必须停在 `needs_capability`，不得读取真实聊天或注册为活动岗位；抖音/小红书不能绕过连接授权。

### 6.2 真实闭环

1. 真实飞书向 A君发送一个公开视频；
2. 内容获取中心或已有产物提供字幕/转录；
3. 小D生成证据链；质量合格时系统自动确认，异常或用户明确要求时转人工确认；
4. 小拆生成正式 `video_content_analysis_report` 并回到原飞书会话；
5. 小创生成 `platform_content_draft`，只供真人审阅；
6. 用户要求归档，小办生成真实 `knowledge_summary_note`；
7. 笔记可在 Obsidian 的统一内容库中打开、搜索且来源有效；
8. 发布后的表现复盘仅在用户提供真实指标后执行。
9. 用户后续只给主题，小创生成一版可拍脚本；用户回复“用这版”后形成受控生产包和 `trial` 模板记录。

### 6.3 完成门禁

- 两个新增岗位各至少完成一次独立、真实、可验收业务闭环；
- 至少一次“公开视频 → 转录/复用 → 自动或人工确认 → 正式拆解 → 飞书交付”；
- 至少一次“当前任务 → 小办总结 → Obsidian 可读笔记”；
- 无 Cookie、token、私密聊天或明文微信数据库进入任务、日志、产物和测试夹具；
- 微信公众号、ChatGPT Web 和微信本地 Vault 在真实验证前保持候选或未注册；创建官生成的微信岗位草案不等于活动岗位或数据授权；
- 验收证据分别记录自动化、本机运行、Hermes/Paperclip、飞书和人工质量，不相互替代。
