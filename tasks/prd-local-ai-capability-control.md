# A君 AI 能力控制中心 PRD

## 目标

A君作为本地 AI 能力的唯一可见控制入口。业务 Agent 只声明需要的能力，不直接管理端口、模型进程或远端机器；能力路由器按需唤醒模型，在首选节点不可用时按已登记策略选择替代节点。

## 用户主流程

1. 用户在 A君的“AI 能力中心”看到 Mac、4070 节点、模型服务、当前负载、启动方式和最近调用者。
2. 用户可对受管服务执行启动、停止、重启、重新检测，并可切换“按需启动”或“禁用”。
3. Agent 请求 `text.generate`、`image.generate` 等能力；路由器根据岗位授权、数据边界和节点健康选择服务。
4. 按需服务未运行时，路由器先启动并等待健康；空闲超过策略阈值后释放模型。
5. 首选服务失败时，只在已登记且满足数据授权的替代路由中切换，并在结果中记录实际提供者与 fallback 原因。

## 异常流程

- 健康检查不得启动重模型；失联显示为失联，并提供显式“重新检测”。
- A君控制入口不可用时，不允许残留的定时任务反复拉起 ComfyUI 等重服务。
- Windows 节点只能停止由节点自身启动的 ComfyUI 子进程；不得结束用户手工启动的 ComfyUI。
- 跨设备传输继续要求本次请求 `approved=true`，不能因为自动 fallback 绕过。
- 服务启动失败、超时、显存不足或节点失联时，返回结构化失败和下一替代路线；无可用替代时明确失败。

## 启动策略

| 组件 | 默认策略 | 说明 |
| --- | --- | --- |
| A君运行台 | 开机运行 | 用户控制入口 |
| Mac AI 网关 18082 | 轻量常驻、可在 A君重启 | 路由、状态、权限与审计，不预加载模型 |
| Qwen3.5 18081 | 按需启动 | 文本、视觉、视频任务触发；空闲释放 |
| Qwen3.6 35B 18080 | 默认禁用的候选 | 只保留人工候选，不进入 Agent 默认路由；不得再藏在 screen 中常驻 |
| Embedding / Reranker | 进程内按需加载 | 空闲释放 |
| Whisper / Qwen3-TTS / MFLUX | 每请求进程 | 请求完成即退出 |
| Windows 18083 节点 | 轻量受管节点 | 提供检测和受管 ComfyUI 控制，不等于 ComfyUI 常驻 |
| Windows ComfyUI 8188 | 按需启动 | 空闲释放；只管理节点自己启动的进程 |

## 验收标准

- A君界面能列出所有上述组件，显示端口、主机、启动策略、状态、最近调用者和动作；18080 不再作为未登记进程存在。
- 停止 Qwen 后健康检查不拉起；发起文本任务会按需拉起并成功返回。
- 停止 ComfyUI 后 4070 节点仍可检测；图片任务可显式唤醒 ComfyUI，失败时回退 Mac MFLUX。
- 禁用某服务后 Agent 调用不会把它启动。
- 任何跨设备 fallback 均保留显式审批门禁。
- 开机项和 Windows 计划任务名称、用途、管理入口均可在 A君看到，不存在未登记的项目服务。
