## 目标

让本机负责人在 `A君运行台 → 系统 → 版本管理` 自己完成 A君代码版本的检查、发布和回滚，不再依赖终端操作。这里的“发布”只指本机 A君运行版本切换，不是抖音、小红书等外部平台发布。

## 主流程

1. “检查新版”只读比较正式仓库当前提交与线上不可变 release。
2. 有新版且仓库干净时，“发布新版”变为可用；点击后再次确认。
3. 系统依次执行源码检查、依赖准备、完整验证、冻结、备份、切换和健康回读。
4. 页面展示真实阶段，不使用百分比；A君重启期间明确提示暂时断开。
5. 新版未通过 PID、工作目录、release 身份和 HTTP 回读时自动恢复旧版。
6. “退回上一版”只恢复最近一次已验证的旧启动配置，并再次验证线上身份。

## 安全边界

- 仅本机负责人、同源页面和短期 owner nonce 可发起写操作。
- 发布助手只接受固定仓库、固定 LaunchAgent、固定端口和固定三种动作。
- 不读取、返回或记录任何 Secret、Cookie、Token 和 Prompt 正文。
- 只发布正式仓库当前已提交的 `main` HEAD；工作区有改动时失败关闭。
- 不执行 `git pull`、提交、推送、合并、强推、依赖升级或其他服务操作。
- 发布期间只允许一个运行；重复请求返回当前运行，不重复切换。

## 验收标准

- [ ] 负责人可以看到当前版本、候选版本、仓库状态和最近一次发布结果。
- [ ] 检查新版不改文件、不重启服务。
- [ ] 发布前有明确二次确认，进行中按钮不可重复点击。
- [ ] 真实发布后新 PID、release hash、Git HEAD、工作目录和 4321 HTTP 一致。
- [ ] 模拟启动失败时自动恢复旧 plist，旧版重新返回 HTTP 200。
- [ ] 用户可以一键退回最近一次已验证旧版。
- [ ] 页面和日志不暴露本机敏感配置或任意命令入口。

## 非目标

- 不提供任意分支、任意路径、任意命令或任意 LaunchAgent 管理。
- 不替代 Git 评审、提交和推送。
- 不控制 Paperclip、Hermes、小D、Publisher 或外部平台发布。
