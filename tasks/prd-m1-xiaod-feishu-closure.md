## 1. 概述

M1 使用现有小D音视频转录整理能力，打通 Agent军团的第一个真实业务闭环。用户在飞书发送音视频链接或任务要求，小D完成获取、转录、整理、产物生成和飞书交付；长任务提供必要状态，失败能够说明原因并按明确边界恢复。

M1 的目的不是增加更多 Agent，而是验证飞书、Hermes 与业务执行器能否通过标准契约协同完成一个可靠任务。Paperclip 按 ADR-0002 从 M2 接入组织治理，不进入 M1 执行关键路径。

## 2. 目标

- 用户无需打开小D网页即可在飞书发起任务并接收结果；
- 任务在 Hermes Kanban 中具有明确归属、执行状态和运行历史；
- 小D通过独立 Hermes Profile 和运行适配层执行现有处理流程；
- 长任务能够展示真实阶段，并支持可控重试或继续；
- 成功交付前验证文档、附件和访问权限；
- 形成可复用于下一个 Agent 的任务、产物、审批和审计基线。

## 3. 目标用户与使用场景

主要用户为 A 君。典型场景：

1. 在飞书向小D发送一个明确授权的公开视频链接；
2. 指定“转录并整理成文章”等任务要求；
3. 收到任务已接收和必要阶段状态；
4. 如输入无效或需要选择，直接在飞书补充；
5. 完成后收到飞书文档、原始转录和任务摘要；
6. 失败时看到真实原因，并可以按提示重试或继续。

## 4. 用户故事

### US-001：从飞书提交小D任务

**描述：** 作为主要用户，我希望把音视频链接和整理要求发给小D，以便直接开始任务。

**验收标准：**

- [ ] 飞书消息能够触发真实任务创建；
- [ ] 系统返回唯一任务 ID 和“已接收”状态；
- [ ] 任务记录原始请求、来源类型、接收人和创建时间；
- [ ] 重复事件不会创建重复任务；
- [ ] 无效或不允许的来源会明确拒绝并说明原因；
- [ ] 自动化测试通过；
- [ ] 使用真实飞书客户端或浏览器环境验证交互。

### US-002：补充缺失信息

**描述：** 作为主要用户，我希望在输入不完整时收到明确问题，以便补充后继续原任务。

**验收标准：**

- [ ] 系统能区分缺少来源、任务要求不明确和来源不可访问；
- [ ] 补充信息关联原任务 ID，不新建无关任务；
- [ ] 等待用户输入期间不显示为执行中；
- [ ] 超过配置期限后任务进入明确的过期或取消状态；
- [ ] 自动化测试通过；
- [ ] 使用真实飞书客户端或浏览器环境验证交互。

### US-003：查看长任务真实阶段

**描述：** 作为主要用户，我希望知道小D当前处于获取、转录、整理还是交付阶段，以便判断任务是否正常。

**验收标准：**

- [x] 至少支持“已接收、获取素材、转录、整理、生成产物、交付”阶段；
- [x] 状态由实际 checkpoint 驱动，不显示虚假百分比；
- [x] 状态通知进行合并或限流，避免刷屏；
- [ ] 后台阶段更新失败不会丢失真实执行状态；
- [x] 自动化测试通过；
- [x] 使用真实飞书客户端或浏览器环境验证交互。

### US-004：交付可访问产物

**描述：** 作为主要用户，我希望在飞书收到可访问的整理文档和原始转录，以便直接查看、下载或继续使用。

**验收标准：**

- [ ] 交付消息包含结果摘要、飞书文档入口和原始转录附件或下载入口；
- [ ] 交付前验证关键产物存在且可读取；
- [ ] 飞书文档权限覆盖预期接收人；
- [ ] 产物记录来源、类型、生成时间和任务 ID；
- [ ] 任一关键产物缺失时不得标记为完整成功；
- [ ] 自动化测试通过；
- [ ] 使用真实飞书客户端或浏览器环境验证交互。

### US-005：处理失败并恢复任务

**描述：** 作为主要用户，我希望任务失败后知道原因和下一步，以便恢复而不是重新猜测流程。

**验收标准：**

- [x] 失败明确区分可重试、需补充输入、需人工处理和永久失败；
- [x] 可重试任务从安全 checkpoint 继续，不重复已确认产物；
- [x] 同一幂等键不会产生重复飞书文档或重复交付通知；
- [x] 恢复失败保留原始错误和新的尝试记录；
- [x] 至少有 1 个真实失败恢复场景通过验收；
- [x] 自动化测试通过；
- [x] 使用真实飞书客户端或浏览器环境验证交互。

### US-006：查看运行任务记录

**描述：** 作为负责人，我希望查看小D任务的归属、运行历史和最终结果，以便判断任务是否真实完成。

**验收标准：**

- [ ] Hermes Kanban 与小D业务记录关联同一个标准任务 ID；
- [ ] 记录承接 Agent、发起人、创建时间、执行状态、尝试历史和最终结果；
- [ ] 小D业务存储保存细粒度 checkpoint，Kanban 不覆盖业务安全断点；
- [ ] 运行历史写入失败被记录并可恢复，不冒充任务已完成；
- [ ] 自动化测试通过。

### US-007：控制高风险交付

**描述：** 作为最终负责人，我希望外部发送等高风险动作在执行前等待批准，以便防止误发或越权。

**验收标准：**

- [ ] 交付给预先授权的内部接收人可以自动完成；
- [ ] 外部发送、公开发布、临时扩权或超过成本阈值时创建审批；
- [ ] 审批拒绝或过期后不执行目标动作；
- [ ] 审批结果与原任务 ID 关联并进入审计记录；
- [ ] M1 没有高风险动作时不强制制造审批步骤；
- [ ] 自动化测试通过；
- [ ] 使用真实飞书客户端或浏览器环境验证交互。

### US-008：保留本地调试入口

**描述：** 作为维护者，我希望现有小D网页继续用于本地调试和应急操作，以便集成故障时能够定位业务执行器。

**验收标准：**

- [ ] 现有网页核心提交、状态和下载能力不因接入改造而丢失；
- [ ] 网页明确标识为调试入口，不作为军团主工作台；
- [ ] 网页与飞书入口使用同一业务执行器和任务契约；
- [ ] 现有自动化测试保持通过；
- [ ] 在浏览器中验证核心路径。

## 5. 功能需求

- **FR-1：** 飞书适配层必须解析任务来源、任务要求、发起人和目标接收人。
- **FR-2：** 每个入站事件必须使用事件 ID 或等价信息实现去重。
- **FR-3：** 任务协调层必须创建标准任务 ID 和幂等键。
- **FR-4：** 任务必须支持 `received`、`needs_input`、`queued`、`acquiring`、`transcribing`、`refining`、`producing_artifacts`、`delivering`、`succeeded`、`failed`、`cancelled` 等标准状态；最终集合以契约文档为准。
- **FR-5：** 运行时必须持久化长任务阶段状态和安全 checkpoint。
- **FR-6：** 飞书状态通知必须按关键阶段发送并支持限流，禁止为每个内部步骤刷屏。
- **FR-7：** 小D必须复用现有素材获取、字幕提取、音频转录、文本整理和 Markdown 产物能力。
- **FR-8：** 系统必须生成或写入飞书文档，并验证读取权限。
- **FR-9：** 系统必须保留原始转录产物，不得只交付模型润色后的文本。
- **FR-10：** 交付消息必须包含任务 ID、结果摘要和产物入口。
- **FR-11：** 失败必须保存错误类别、原始原因、发生阶段和是否可重试。
- **FR-12：** 重试必须从安全 checkpoint 开始并避免重复产物与通知。
- **FR-13：** Hermes 适配层必须保存执行任务、尝试和运行历史，并与小D checkpoint 使用同一标准任务 ID。
- **FR-14：** 高风险动作必须经过统一审批契约；普通内部交付默认不审批。
- **FR-15：** 所有日志必须过滤 secret、token、Cookie、授权链接和不必要的原始私人内容。

## 6. 状态与完成定义

### 6.1 状态原则

- 飞书展示面向用户的少量阶段；
- 运行时保存足以恢复的细粒度 checkpoint；
- Hermes Kanban 保存执行任务与运行历史；
- 小D业务存储保存细粒度 checkpoint；
- 状态映射由协调层统一维护。

### 6.2 完整成功

任务只有同时满足以下条件才可标记为 `succeeded`：

- 必要处理阶段完成；
- 原始转录产物存在；
- 整理产物存在；
- 飞书交付产物存在且预期接收人可访问；
- 最终交付消息发送成功或进入可补偿的明确状态；
- 运行历史已记录最终结果，或记录失败已进入可恢复状态且不冒充已记录。

## 7. 飞书交互要求

M1 原型和实现必须覆盖：

- 发起任务；
- 已接收；
- 处理中；
- 需要补充信息；
- 按需审批；
- 成功交付；
- 失败与恢复。

首屏或消息卡片只展示当前任务、当前状态、主要操作和必要结果。日志、技术错误、成本明细和低频配置通过任务详情查看；M2 接入 Paperclip 后再增加组织治理视图。

## 8. 技术考虑

- 现有应用位于 `apps/xiaod-media-transcriber/`，改造必须保留既有功能和历史产物；
- 飞书和 Hermes 接入必须通过 `integrations/` 下的适配层；
- 小D业务核心不得直接调用飞书或 Hermes SDK；
- 接入前先验证当前租户和版本的真实 API、事件、卡片、审批与权限能力；
- 如果 Hermes 缺少必要扩展点，先通过适配层补齐，不静默更换总体架构；
- M1 不安装或接入 Paperclip，不建设临时治理后台；
- 不把 `.env`、真实 token 或用户私人内容写入 PRD、测试快照或验收证据。

## 9. 非目标

- 不新增其他业务 Agent；
- 不开发自有军团管理后台；
- 不建设多租户、公开注册和商业计费；
- 不自动发布到公开平台；
- 不绕过登录、付费、Cookie 或来源访问控制；
- 不在 M1 引入与真实闭环无关的复杂工作流引擎；
- 不对现有小D调试网页进行无关的大规模视觉重构。

## 10. 验收方案

### 10.1 自动化验证

- 现有小D测试全部通过；
- 新增任务状态、幂等、失败分类和权限判断单元测试；
- 新增飞书、Hermes 适配器契约测试；
- 新增从任务创建到产物交付的集成测试；
- 日志脱敏测试覆盖凭据和敏感字段。

### 10.2 真实运行验收

至少完成：

1. 一个短视频正常闭环；
2. 一个长音视频任务，验证阶段状态与最终交付；
3. 一个重复飞书事件，验证不创建重复任务；
4. 一个输入无效或来源不可访问场景；
5. 一个中途失败后从 checkpoint 恢复的场景；
6. 一个产物权限读取验证；
7. 如 M1 实际包含高风险动作，一个批准和一个拒绝场景。

每次验收记录代码版本、运行目录、监听进程、使用入口、任务 ID、结果和证据位置，不记录凭据或不必要的私人内容。

## 11. 成功指标

- 3 次真实飞书任务端到端成功，其中至少 1 次长任务；
- 关键任务丢失率 0；
- 重复事件导致的重复任务数 0；
- 成功任务关键产物可访问率 100%；
- 至少 1 次失败恢复成功；
- 未经批准执行高风险动作次数 0；
- 现有小D核心功能和测试无回归；
- M1 验收后总 PRD、根 README、架构、契约和验收记录同步更新。

## 12. 已确认边界与真实验证项

只读验证已确认：Hermes 提供飞书 Gateway、Profile 路由和 Kanban 运行能力；Lark CLI/飞书工具集可作为文档、云盘和权限工具层；Paperclip 延后到 M2。

真实环境仍需验证：

- 当前飞书租户可用的消息事件、卡片回调和用户准入；
- 飞书文档创建、内容写入、权限授予和接收人读取；
- 隔离 `xiaod` Hermes Profile 的任务提交、失败、重试、取消和重启恢复；
- Lark CLI 与 Hermes 飞书工具哪条文档交付路径在当前租户更稳定。

以上项目必须用测试群、测试文档和短素材验证，不允许用只读能力判断替代真实验收。
