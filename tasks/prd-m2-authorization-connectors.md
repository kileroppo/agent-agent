## 1. 概述

随着小D之外的业务 Agent 需要读取网站或软件中的数据，登录授权和内容获取都不能散落在各 Agent、飞书消息或脚本中。本里程碑以 **Paperclip** 作为军团的公司总控：它统一承载组织、目标、任务、heartbeat 调度、预算、审批和审计；以 **A君本地运行时** 作为可扩展的本机能力底座与执行适配层：用户安装 A君，而不是分别安装、启动和维护多个下载器、爬虫、Cookie 同步器或命令行工具。日常任务仍从飞书发送给对应 Agent；A君只在授权、诊断、恢复和必要的应急手工入口中面向用户。A君在内部管理账号连接、内容获取、媒体处理、平台适配器和运维观察；用户本人只在必要时通过 A君官方浏览器伴侣或 OAuth 完成登录。

这不是“把 Cookie 交给 Agent”，也不是让运维官替用户登录。它由三个公共能力组成：统一账号管家、以 MediaCrawlerPro 优先且通用能力兜底的内容获取中心、以及 Agent 运维官。它们服务所有业务 Agent；小D只是第一个预期消费者。独立软件不等于没有任何第三方依赖，而是依赖的安装、启动、更新、健康检查与版本兼容由 A君负责，不能变成用户的运维负担。

Paperclip 不是仅记录治理结果的旁路看板。完成验证后，它负责唤醒和管理接入的 Agent 运行时；A君向它提供本机业务 Agent 的受控执行入口、标准化回报和可验证产物引用。A君不另建军团组织图、任务队列、定时调度、预算或审批后台。

## 2. 目标与非目标

### 目标

- 用户能为一个网站或软件连接创建、查看、续期和撤销授权；
- Paperclip 能管理至少一个接入 Agent 的岗位、任务、heartbeat、预算、审批与审计；
- A君 能把一个本机业务任务以受控适配器接入 Paperclip，并把真实执行状态和产物引用回报给 Paperclip；
- Agent 通过命名连接和受限操作访问数据，永不读取密码、Cookie、token 或完整登录态；
- 授权范围明确绑定平台、账户别名、允许动作、可使用 Agent、有效期与审批规则；
- 授权过期、撤销、权限不足或平台不可用时，任务得到真实、可恢复的状态；
- 运维与审核只读取脱敏健康状态和审计元数据，能够发现平台级故障与越权请求。
- 用户面对一个 A君桌面应用和必要时的官方浏览器伴侣；内部运行时由 A君一键启动、更新、诊断和停止；
- 媒体处理、ASR、公开媒体下载、平台适配器等以 A君受控组件交付，不能要求用户手工执行命令或维护端口；
- 每个内置或可选组件都声明许可证、来源、版本、支持平台、能力范围和健康探针，便于更新、替换或下线。
- 所有 Agent 通过统一内容获取中心请求正文、图片、视频、字幕、基本信息或平台深度内容，永不直接绑定 `yt-dlp`、MediaCrawlerPro、浏览器工具或其他具体实现；
- 固定平台优先使用 MediaCrawlerPro 深度适配器；其不可用或不支持时按请求能力切换到通用内容获取，结果如实标明本次可提供的能力范围，而不把通用结果误称为失败或“内容不完整”；
- 运维官能从脱敏健康元数据发现连接失效、工具故障、连续任务失败和通道切换，并执行通知、诊断、低风险重试及 A君自管组件的恢复。

### 非目标

- 不在飞书、任务正文、日志或文档中传输、粘贴或展示 Cookie、密码、token、授权 URL；
- 不绕过验证码、二次验证、付费墙、地区限制、平台反爬或内容访问控制；
- 不让“架构师”“运维官”或“技术专家”获得所有外部账号的原始凭据；
- 不在本 PRD 中承诺所有视频平台都已支持，具体平台须各自通过适配与真实验收；
- 不把 M1 已验证的本地文件/公开来源路径改造成依赖登录的路径。
- 不承诺把不符合许可证、分发要求、平台条款或安全审查的第三方代码直接打包进产品；必要时以自研适配器、官方 API 或可选连接器替代；
- 不把“用户浏览器已登录”误称为 A君已获得无限平台权限；登录型平台仍须逐连接、逐动作授权。
- 不建设与 Paperclip 重复的军团控制台、组织树、任务队列、心跳调度、预算或审批系统；
- 不因接入 Paperclip 而把未授权的外部连接、飞书写入、发布、删除、付费或扩权动作自动开放给 Agent。

## 3. 用户流程

```text
用户或业务 Agent 提交链接与所需内容范围
→ 统一内容获取中心识别平台、已注册适配器和是否需要登录
→ 若没有可用授权：任务进入 needs_input，并给出“授权该连接”入口
→ 用户在受控浏览器或官方 OAuth 页面自行完成登录
→ 账号管家仅保存安全凭据引用与脱敏元数据
→ 内容中心优先调用该平台的 MediaCrawlerPro 深度适配器；不能使用时调用通用内容适配器
→ 内容中心返回平台无关的内容包，标明本次获取通道与实际提供的能力
→ 业务 Agent 使用内容包完成自己的工作
→ 连接失效、适配器故障或平台限制由运维官记录、诊断并给出恢复动作
```

“需要补充”指用户完成授权或选择替代来源，不指用户向聊天粘贴 Cookie。

### 3.1 用户看到的安装形态

```text
用户安装：A君.app
  → 首次启动：A君自动准备并启动本地运行时
  → 常规任务：在飞书中直接交给小D或其他 Agent
  → 仅在某个平台需要登录时：A君提示安装/启用自己的浏览器伴侣，用户本人完成登录
  → 后续任务：A君复用已授予的命名连接，无需用户启动任何脚本或后台服务
```

浏览器伴侣是 A君产品的一部分，不是要求用户理解或配置 CookieBridge、AutoCLI、bb-browser 等研发工具。用户可禁用、撤销或卸载该伴侣；不需要登录的平台不要求安装它。

## 4. 用户故事与验收

### US-201：建立受控连接

作为负责人，我希望自己完成一个网站或软件的登录授权，以便获准的 Agent 可使用该连接。

- [ ] 用户在受控入口完成登录或 OAuth，不通过聊天粘贴凭据；
- [ ] 连接记录仅保存平台、账户别名、状态、授权范围、有效期和安全凭据引用；
- [ ] 凭据实际存放在系统密钥链或受控密钥存储，应用数据、日志、测试夹具和审计记录不包含原始值；
- [ ] 连接可被续期、撤销或禁用；
- [ ] 自动化测试覆盖脱敏与状态推进；
- [ ] 至少一个低风险、已授权平台完成真实连接验证。

### US-202：按能力使用连接

作为业务 Agent，我希望只获得完成任务所需的受限连接能力，而不是账号原始凭据。

- [ ] Agent 调用以 `connectionId + operation` 表达，例如 `read_media_metadata` 或 `download_authorized_media`；
- [ ] 每次调用核对平台、允许动作、Agent、数据范围、有效期和必要审批；
- [ ] 范围不匹配、连接缺失、过期、撤销或账户权限不足时默认拒绝；
- [ ] 业务任务把上述情况映射为 `needs_input`、`waiting_approval`、`manual` 或 `permanent`，不伪造成功；
- [ ] Agent、模型输出和飞书投影无法读取或回显原始凭据；
- [ ] 自动化测试覆盖允许、越权、过期和撤销四种路径。

### US-203：治理与恢复

作为负责人，我希望授权问题可追踪、可恢复且不会静默影响业务任务。

- [ ] 审计记录关联连接、任务、Agent、动作、结果和时间，但不包含敏感值或受限内容；
- [ ] 运维健康检查能区分正常、即将过期、已过期、已撤销和平台错误；
- [ ] 同一平台出现阈值内的连续失败时创建脱敏运维事件，而非让每个任务重复猜测；
- [ ] 运维官只能看到健康状态和事件，不能导出或读取凭据；
- [ ] 技术专家的修复建议不自动扩大授权；扩大范围须由审核策略和负责人确认；
- [ ] 真实授权过期或撤销后的任务恢复流程至少验证一次。

### US-204：跨 Agent 获取外部内容

作为业务 Agent，我希望用同一种请求方式获取不同网站的内容，以便不关心底层是哪个下载器、爬虫或浏览器工具。

- [ ] 请求只表达来源、所需内容能力和可选连接，不指定底层工具；
- [ ] 已支持的固定平台优先通过 MediaCrawlerPro 深度适配器获取，可返回评论等平台能力；
- [ ] 深度适配器不支持或不可用时，按能力规则切换到通用内容适配器；
- [ ] 通用适配器可返回其已声明能力范围内的正文、图片、视频、字幕和基本信息；
- [ ] 内容包标明来源、获取通道、实际提供的能力和安全的能力说明；
- [ ] Agent 不读取浏览器会话或原始凭据，且不得因替换底层工具而修改业务流程。

### US-205：运维官观察公共能力

作为负责人，我希望运维官持续发现公共能力的异常，以便问题不会在每个 Agent 中重复出现。

- [ ] 运维官读取连接、内容适配器和任务的脱敏健康事件；
- [ ] 连续失败、登录失效、工具不可用和通道切换能形成可追踪事件；
- [ ] 第一阶段只执行诊断、通知、低风险重试和 A君自管组件恢复；
- [ ] 重新登录、验证码、二次验证、付费权限和授权扩大必须由用户完成或批准；
- [ ] 运维事件不包含原始凭据、私密内容或完整浏览器会话。

## 5. 领域边界与数据真相

| 数据 | 真相来源 | 禁止内容 |
| --- | --- | --- |
| 连接定义、范围、状态与授权引用 | 授权连接器存储 | 密码、Cookie、token 原文 |
| 凭据实际值 | 系统密钥链或受控密钥存储 | 业务任务、Agent Prompt、聊天、日志 |
| 适配器能力、平台覆盖与优先级 | 内容获取中心的适配器注册表 | 由业务 Agent 在任务中临时指定或修改 |
| 单次内容请求、内容包与能力说明 | 内容获取中心与业务 checkpoint | 原始凭据、浏览器会话和未授权私密数据 |
| Agent 的可用动作与审批规则 | AgentManifest + 授权策略 | 以展示名临时猜测权限 |
| 单次调用与业务结果 | TaskContract / 业务 checkpoint | 用“连接正常”冒充业务成功 |
| 健康、过期与审计元数据 | 治理控制面 | 受限媒体内容与凭据 |
| 军团目标、组织、岗位、组织级任务、heartbeat、预算、审批和审计 | Paperclip | A君本地页面或业务 Agent 私自维护的第二套真相 |
| 本机业务执行过程、checkpoint 和可验证产物 | A君业务运行时 / 业务 Agent | 将部分成功投射为 Paperclip 完成 |

连接器是工具适配层能力；业务 Agent 保持平台无关。对站点的具体浏览器自动化、官方 API 或下载方式必须实现为独立适配器，并各自声明支持动作和失败分类。

### 5.1 A君运行时封装边界

| 用户可见 | A君内部管理 | 外部边界 |
| --- | --- | --- |
| A君桌面应用的连接管理、授权状态、组件健康、恢复提示与脱敏诊断；飞书交付 | Agent 运行时、Connection Broker、媒体 Worker、ASR 模型、平台适配器、健康检查、更新器 | 飞书、用户自行登录的浏览器/OAuth、平台网站、可选模型服务 |
| “连接小红书”“转录链接”“重新授权” | `yt-dlp`、MediaCrawler 能力或其他经审查组件的封装实现 | 平台最终是否允许访问、是否要求验证码/二次验证、官方 API 可用性 |

产品不暴露内部端口、命令、原始凭据或依赖名称给日常用户。技术负责人可以在受控诊断界面查看**脱敏**组件版本与健康状态；出现故障时，A君给出“修复/更新/重新授权/改用本地文件”等恢复动作，而非让用户到终端执行命令。

### 5.2 现有工具的复用边界

已调研的工具提供了可复用的底层能力，但均不能替代本 PRD 的授权与治理边界。

| 工具 | 可采纳的能力 | 在 M2 中的位置 | 明确不采纳 |
| --- | --- | --- | --- |
| `yt-dlp` | 公开或已获准媒体的确定性下载与字幕优先获取 | `PublicMediaAdapter` 或受控平台适配器内部实现 | 将浏览器 Cookie 或命令行参数暴露给小D、Hermes、模型或日志 |
| MediaCrawlerPro / CookieBridge | 中文平台路由、素材解析和浏览器登录态同步 | `MediaCrawlerAdapter` 的候选底层实现；CookieBridge 只由授权网关进程内部通过 loopback 调用，临时登录态只递给 MediaCrawlerPro | 将 CookieBridge 作为全局 Agent API，或把其原始 Cookie 返回给任务、页面、日志或 Agent |
| `web-access` | 人工辅助登录、网页验证和受控浏览器操作 | 用户授权流程或人工排障工具，不作为后台任务执行器 | 后台任务直接操纵用户既有标签页，或把浏览器会话交给任意 Agent |
| `agent-reach` / `scout` | 平台分类、URL 路由和失败提示的参考规则 | 适配器注册表与预检规则的输入 | 其“让用户提交 Cookie”的交互方式 |
| `mvanhorn/last30days-skill` | 多来源研究、来源健康诊断和配置缺失提示 | 后续“研究/情报”业务 Agent 的独立工具；可借鉴连接器 `doctor` 的脱敏诊断体验 | 将它作为小D下载器，或把研究源的浏览器凭据扩散给其他 Agent |
| `nashsu/AutoCLI` | 声明式平台适配器、结构化输出和公开/浏览器能力分级 | 适配器规范的参考；未来可在授权网关内部做受限读取型执行器 | 让模型自动生成并立即启用适配器；开放其发布、删除、私信等命令 |
| `epiral/bb-browser` | 真实浏览器会话桥接、按平台命令返回结构化结果 | 仅作为授权网关内部的候选浏览器执行后端 | 让业务 Agent 直接执行任意 `eval`、网络拦截、页面模块注入或跨站调用 |

这三项新参考工具均以“复用用户浏览器登录态”为核心。因此它们解决的是**平台动作执行**，不是授权治理。M2 必须先在其外层完成 `connectionId + operation` 策略校验；执行器只收到经过允许的、一次性的读取请求，并只能返回规范化素材引用或脱敏失败原因。

### 5.3 已确认的公共能力边界

```text
所有业务 Agent
  └─ 内容获取中心.fetch(source, requestedCapabilities, connectionId?)
       ├─ 平台与能力预检：只查注册表，不让 Agent 选择具体工具
       ├─ 账号管家：检查连接范围、有效期、Agent、操作与审批
       ├─ 深度通道：MediaCrawlerAdapter（固定平台、可含评论）
       ├─ 通用通道：PublicMediaAdapter / BrowserContentAdapter（公开或已授权读取）
       ├─ 内容标准化：返回统一 ContentPackage 与能力说明
       └─ 运维事件：健康、切换、连续失败和恢复建议
```

- 账号管家接受受控浏览器登录、OAuth、CookieBridge 或其他本机导入适配器；它对工具输出的是受限的“本次可用连接”，不把原始 Cookie 作为公共 API 输出；
- 内容获取中心把“MediaCrawlerPro 深度通道优先、通用通道兜底”固定为路由策略。通用通道是独立能力范围，不以“深度通道不可用”自动标记为内容失败；
- MediaCrawlerPro、`yt-dlp`、`bb-browser`、`web-access`、CookieBridge 或未来工具都必须位于可替换适配器后面；上层只依赖统一契约；
- 运维官只消费脱敏事件和执行恢复策略，不读取凭据或内容，也不替用户完成登录、验证码或越权操作。

### 5.4 首个技术切片

```text
业务 Agent / 小D
  └─ ContentAcquisitionCenter.fetch(source, requestedCapabilities, connectionId?)
       ├─ ConnectionBroker：策略检查 Agent、平台、动作、数据范围、有效期、审批
       ├─ MediaCrawlerAdapter：已支持平台优先获取深度内容
       ├─ GeneralContentAdapter：通用正文、图片、视频、字幕和基本信息获取
       ├─ 凭据边界：仅账号管家/执行器进程内部可访问安全凭据引用或浏览器会话
       └─ 返回：ContentPackage / SafeFailure（不含凭据）
```

首个切片只允许一个已获用户明确授权的平台、一个只读操作和一个具体 URL；实现连接注册、一个深度适配器、一个通用适配器和一个脱敏运维事件。它不开放 AutoCLI、bb-browser 所具备的发布、删除、互动、私信、网络拦截或任意脚本能力。适配器新增和平台动作扩展均应先经过审核策略，而不是由模型在任务中自行发现后上线。

## 6. 实施顺序

1. 已验证当前 Paperclip `2026.707.0` 的公司、Agent、任务、heartbeat、运行时 HTTP Adapter、审计与回报 API；预算和审批需在后续带对应策略的真实任务中验证；
2. 在 Paperclip 建立 Agent军团组织和首个低风险本机执行 Agent；将岗位清单/权限从仓库 Manifest 受控同步或映射，不手工维护第二套组织真相；
3. 为 A君实现一个最小执行适配器：接收 Paperclip heartbeat，领取一个任务，调用受限本机业务能力，回报阶段、产物引用、成本/失败分类；
4. 收口 A君页面为连接授权、组件健康、恢复操作和脱敏诊断入口；日常业务派活与交付只在飞书进行，组织、任务调度、预算和审批只在 Paperclip 管理；
5. 实现连接注册、受控授权入口、密钥存储适配和 `ConnectionBroker` 策略检查；
6. 实现内容获取中心、适配器注册表和平台无关的内容包；
7. 为首个平台实现一个 MediaCrawlerPro 深度适配器，并实现一个通用内容适配器；若复用浏览器会话，执行器必须在账号管家的受限进程边界内运行；
8. 实现运维官的脱敏健康事件、诊断和低风险恢复；
9. 仅选择一个低风险、明确授权的平台和一个具体 URL 验证，再让小D通过统一内容包接入；
10. 验证过期/撤销、深度通道切换到通用通道、Paperclip 预算拦截、审批拒绝和运维提醒；
11. 第二个真实消费者出现后才提取共享实现到 `packages/`。

每个平台新增“读取”以外的动作（发布、删除、修改设置、付费）均须单独评估审批策略，不能从读取授权推导出来。

## 7. 完成定义

M2 的这项能力只有在“Paperclip 创建/分配一个低风险任务 → heartbeat 唤醒接入的 Agent → A君受控调用本机业务能力 → Agent 回报真实阶段、成本与产物引用 → Paperclip 展示任务、预算、审批与审计结果 → 用户无需手工启动内部组件完成一个真实低风险连接读取 → 内容中心按能力范围切换并由小D或另一业务 Agent 消费统一内容包 → 运维官产生脱敏事件并执行安全恢复 → 过期或撤销后可恢复”的闭环后，才可标为已验收。代码、健康探针、已登录浏览器或 A君单独页面本身都不代表该闭环通过。
