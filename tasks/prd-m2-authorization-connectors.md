## 1. 概述

随着小D之外的业务 Agent 需要读取网站或软件中的数据，登录授权不能散落在各 Agent、飞书消息或脚本中。本里程碑把当前研发期的分散工具能力收敛为 **A君本地运行时**：用户安装 A君，而不是分别安装、启动和维护多个下载器、爬虫、Cookie 同步器或命令行工具。运行时在内部管理媒体处理、授权连接器和平台适配器；用户本人只在必要时通过 A君官方浏览器伴侣或 OAuth 完成登录。

这不是“把 Cookie 交给 Agent”，也不是让运维官替用户登录。它是所有业务 Agent 可复用的受控基础能力；小D是第一个预期消费者。独立软件不等于没有任何第三方依赖，而是依赖的安装、启动、更新、健康检查与版本兼容由 A君负责，不能变成用户的运维负担。

## 2. 目标与非目标

### 目标

- 用户能为一个网站或软件连接创建、查看、续期和撤销授权；
- Agent 通过命名连接和受限操作访问数据，永不读取密码、Cookie、token 或完整登录态；
- 授权范围明确绑定平台、账户别名、允许动作、可使用 Agent、有效期与审批规则；
- 授权过期、撤销、权限不足或平台不可用时，任务得到真实、可恢复的状态；
- 运维与审核只读取脱敏健康状态和审计元数据，能够发现平台级故障与越权请求。
- 用户面对一个 A君桌面应用和必要时的官方浏览器伴侣；内部运行时由 A君一键启动、更新、诊断和停止；
- 媒体处理、ASR、公开媒体下载、平台适配器等以 A君受控组件交付，不能要求用户手工执行命令或维护端口；
- 每个内置或可选组件都声明许可证、来源、版本、支持平台、能力范围和健康探针，便于更新、替换或下线。

### 非目标

- 不在飞书、任务正文、日志或文档中传输、粘贴或展示 Cookie、密码、token、授权 URL；
- 不绕过验证码、二次验证、付费墙、地区限制、平台反爬或内容访问控制；
- 不让“架构师”“运维官”或“技术专家”获得所有外部账号的原始凭据；
- 不在本 PRD 中承诺所有视频平台都已支持，具体平台须各自通过适配与真实验收；
- 不把 M1 已验证的本地文件/公开来源路径改造成依赖登录的路径。
- 不承诺把不符合许可证、分发要求、平台条款或安全审查的第三方代码直接打包进产品；必要时以自研适配器、官方 API 或可选连接器替代；
- 不把“用户浏览器已登录”误称为 A君已获得无限平台权限；登录型平台仍须逐连接、逐动作授权。

## 3. 用户流程

```text
用户发送需要登录的网站或软件链接
→ 业务 Agent 预检来源与所需权限
→ 若没有可用授权：任务进入 needs_input，并给出“授权该连接”入口
→ 用户在受控浏览器或官方 OAuth 页面自行完成登录
→ 授权连接器仅保存安全凭据引用与脱敏元数据
→ 审核策略确认 Agent、动作和数据范围匹配
→ 业务 Agent 使用命名连接执行读取/下载等已允许操作
→ 连接过期、撤销或权限不足：任务停止在明确状态并请求重新授权或人工处理
```

“需要补充”指用户完成授权或选择替代来源，不指用户向聊天粘贴 Cookie。

### 3.1 用户看到的安装形态

```text
用户安装：A君.app
  → 首次启动：A君自动准备并启动本地运行时
  → 常规任务：在飞书或 A君中直接交给小D
  → 仅在某个平台需要登录时：A君提示安装/启用自己的浏览器伴侣，用户本人完成登录
  → 后续任务：A君复用已授予的命名连接，无需用户启动任何脚本或后台服务
```

浏览器伴侣是 A君产品的一部分，不是要求用户理解或配置 CookieBridge、AutoCLI、bb-browser 等研发工具。用户可禁用、撤销或卸载该伴侣；不需要登录的平台不要求安装它。

## 4. 用户故事与验收

### US-201：建立受控连接

作为负责人，我希望自己完成一个网站或软件的登录授权，以便获准的 Agent 可使用该连接。

- [ ] 用户在受控入口完成登录或 OAuth，不通过聊天粘贴凭据；
- [ ] 连接记录仅保存平台、账户别名、状态、授权范围、有效期和安全凭据引用；
- [ ] 凭据实际存放在系统密钥链或受控密钥存储，应用数据、日志、测试夹具和审计记录不包含原始值；
- [ ] 连接可被续期、撤销或禁用；
- [ ] 自动化测试覆盖脱敏与状态推进；
- [ ] 至少一个低风险、已授权平台完成真实连接验证。

### US-202：按能力使用连接

作为业务 Agent，我希望只获得完成任务所需的受限连接能力，而不是账号原始凭据。

- [ ] Agent 调用以 `connectionId + operation` 表达，例如 `read_media_metadata` 或 `download_authorized_media`；
- [ ] 每次调用核对平台、允许动作、Agent、数据范围、有效期和必要审批；
- [ ] 范围不匹配、连接缺失、过期、撤销或账户权限不足时默认拒绝；
- [ ] 业务任务把上述情况映射为 `needs_input`、`waiting_approval`、`manual` 或 `permanent`，不伪造成功；
- [ ] Agent、模型输出和飞书投影无法读取或回显原始凭据；
- [ ] 自动化测试覆盖允许、越权、过期和撤销四种路径。

### US-203：治理与恢复

作为负责人，我希望授权问题可追踪、可恢复且不会静默影响业务任务。

- [ ] 审计记录关联连接、任务、Agent、动作、结果和时间，但不包含敏感值或受限内容；
- [ ] 运维健康检查能区分正常、即将过期、已过期、已撤销和平台错误；
- [ ] 同一平台出现阈值内的连续失败时创建脱敏运维事件，而非让每个任务重复猜测；
- [ ] 运维官只能看到健康状态和事件，不能导出或读取凭据；
- [ ] 技术专家的修复建议不自动扩大授权；扩大范围须由审核策略和负责人确认；
- [ ] 真实授权过期或撤销后的任务恢复流程至少验证一次。

## 5. 领域边界与数据真相

| 数据 | 真相来源 | 禁止内容 |
| --- | --- | --- |
| 连接定义、范围、状态与授权引用 | 授权连接器存储 | 密码、Cookie、token 原文 |
| 凭据实际值 | 系统密钥链或受控密钥存储 | 业务任务、Agent Prompt、聊天、日志 |
| Agent 的可用动作与审批规则 | AgentManifest + 授权策略 | 以展示名临时猜测权限 |
| 单次调用与业务结果 | TaskContract / 业务 checkpoint | 用“连接正常”冒充业务成功 |
| 健康、过期与审计元数据 | 治理控制面 | 受限媒体内容与凭据 |

连接器是工具适配层能力；业务 Agent 保持平台无关。对站点的具体浏览器自动化、官方 API 或下载方式必须实现为独立适配器，并各自声明支持动作和失败分类。

### 5.1 A君运行时封装边界

| 用户可见 | A君内部管理 | 外部边界 |
| --- | --- | --- |
| A君桌面应用、飞书交付、连接管理、授权状态与恢复提示 | Agent 运行时、任务存储、Connection Broker、媒体 Worker、ASR 模型、平台适配器、健康检查、更新器 | 飞书、用户自行登录的浏览器/OAuth、平台网站、可选模型服务 |
| “连接小红书”“转录链接”“重新授权” | `yt-dlp`、MediaCrawler 能力或其他经审查组件的封装实现 | 平台最终是否允许访问、是否要求验证码/二次验证、官方 API 可用性 |

产品不暴露内部端口、命令、原始凭据或依赖名称给日常用户。技术负责人可以在受控诊断界面查看**脱敏**组件版本与健康状态；出现故障时，A君给出“修复/更新/重新授权/改用本地文件”等恢复动作，而非让用户到终端执行命令。

### 5.2 现有工具的复用边界

已调研的工具提供了可复用的底层能力，但均不能替代本 PRD 的授权与治理边界。

| 工具 | 可采纳的能力 | 在 M2 中的位置 | 明确不采纳 |
| --- | --- | --- | --- |
| `yt-dlp` | 公开或已获准媒体的确定性下载与字幕优先获取 | `PublicMediaAdapter` 或受控平台适配器内部实现 | 将浏览器 Cookie 或命令行参数暴露给小D、Hermes、模型或日志 |
| MediaCrawlerPro / CookieBridge | 中文平台路由、素材解析和浏览器登录态同步 | `MediaCrawlerAdapter` 的候选底层实现；CookieBridge 只由授权网关进程内部访问 | 直接调用会返回原始 Cookie 的 CookieBridge HTTP API；将 CookieBridge 作为全局 Agent API |
| `web-access` | 人工辅助登录、网页验证和受控浏览器操作 | 用户授权流程或人工排障工具，不作为后台任务执行器 | 后台任务直接操纵用户既有标签页，或把浏览器会话交给任意 Agent |
| `agent-reach` / `scout` | 平台分类、URL 路由和失败提示的参考规则 | 适配器注册表与预检规则的输入 | 其“让用户提交 Cookie”的交互方式 |
| `mvanhorn/last30days-skill` | 多来源研究、来源健康诊断和配置缺失提示 | 后续“研究/情报”业务 Agent 的独立工具；可借鉴连接器 `doctor` 的脱敏诊断体验 | 将它作为小D下载器，或把研究源的浏览器凭据扩散给其他 Agent |
| `nashsu/AutoCLI` | 声明式平台适配器、结构化输出和公开/浏览器能力分级 | 适配器规范的参考；未来可在授权网关内部做受限读取型执行器 | 让模型自动生成并立即启用适配器；开放其发布、删除、私信等命令 |
| `epiral/bb-browser` | 真实浏览器会话桥接、按平台命令返回结构化结果 | 仅作为授权网关内部的候选浏览器执行后端 | 让业务 Agent 直接执行任意 `eval`、网络拦截、页面模块注入或跨站调用 |

这三项新参考工具均以“复用用户浏览器登录态”为核心。因此它们解决的是**平台动作执行**，不是授权治理。M2 必须先在其外层完成 `connectionId + operation` 策略校验；执行器只收到经过允许的、一次性的读取请求，并只能返回规范化素材引用或脱敏失败原因。

### 5.3 建议的技术切片

```text
业务 Agent / 小D
  └─ ConnectionBroker.execute(connectionId, operation, source)
       ├─ 策略检查：Agent、平台、动作、数据范围、有效期、审批
       ├─ 执行器选择：公开来源 -> yt-dlp；已授权中文平台 -> MediaCrawlerAdapter；
       │             需要浏览器会话的读取 -> 受限 BrowserSessionAdapter
       ├─ 凭据边界：仅 Broker/执行器进程内部可访问安全凭据引用或浏览器会话
       └─ 返回：SourceAssetRef / SubtitleRef / SafeFailure（不含凭据）
```

首个切片只允许一个已获用户明确授权的平台、一个只读操作和一个具体 URL；不开放 AutoCLI、bb-browser 所具备的发布、删除、互动、私信、网络拦截或任意脚本能力。适配器新增和平台动作扩展均应先经过审核策略，而不是由模型在任务中自行发现后上线。

## 6. 实施顺序

1. 先定义 A君本地运行时的组件清单、生命周期、更新策略、许可证/来源清单和脱敏诊断面；
2. 实现 A君启动器的最小垂直切片：一次启动本地核心与媒体 Worker，并在 A君内显示健康状态，不要求用户手工启动服务；
3. 实现 `ConnectionBroker.execute(connectionId, operation, source)`、连接注册、受控授权入口、密钥存储适配和策略检查；
4. 为首个平台实现一个只读平台适配器；若复用浏览器会话，执行器必须在 Broker 的受限进程边界内运行；
5. 仅选择一个低风险、明确授权的平台和一个具体 URL 验证；
6. 小D通过命名连接接入该平台；
7. 再接入过期/撤销、运维健康和治理投影；
8. 第二个真实消费者出现后才提取共享实现到 `packages/`。

每个平台新增“读取”以外的动作（发布、删除、修改设置、付费）均须单独评估审批策略，不能从读取授权推导出来。

## 7. 完成定义

M2 的这项能力只有在 A君运行时已做到“用户无需手工启动内部组件 → 一个真实低风险连接完成用户授权 → 小D或另一业务 Agent 受限调用 → 脱敏审计 → 过期或撤销 → 安全恢复”的闭环后，才可标为已验收。代码、健康探针或已登录浏览器本身都不代表该闭环通过。
